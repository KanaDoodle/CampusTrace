# 岗位匹配与求职资料

这里保留 README 中较详细的使用说明与匹配规则。快速上手见 [README](../README.md)。

## 投递条件、Go 方向与初筛优先级

Eligibility 分别检查毕业年份、学历、岗位类型、地点、经验、专业、语言和技术要求。毕业年份、学历或岗位类型缺少证据时属于关键 `UNKNOWN`；明确硬性不符优先，未解决的证据问题优先于偏好条件。

地点和偏好岗位类型属于 `CONDITIONAL` 偏好，不伪装成硬性资格约束。已识别的专业、语言和经验要求可以成为硬约束；可选技术信号不能覆盖明确的 `REQUIRED:` 条件。

投递条件核对中的「我的情况」始终来自已保存的求职资料，不依赖岗位要求是否提取成功。地点展示首选与可接受城市，毕业届别支持年份范围。岗位侧缺少证据时显示「尚未提取到明确要求」，个人侧确实为空时显示「求职资料中尚未填写」；缺少岗位证据仍保留 `UNKNOWN`，不会仅凭资料完整就判为满足。

GoFit 独立输出 `EXPLICIT_GO`、`LANGUAGE_FLEXIBLE`、`NO_GO_SIGNAL`、`CONFLICTING` 或 `UNKNOWN`。Ranking 使用可见的加权分解，通过 `RANKING_WEIGHTS` 配置全部权重；`breakdown_sources` 区分证据判断、用户偏好和岗位/观察元数据。

离线 parser 仅保守支持 [导入示例](../testdata/import.json) 中的显式标签，以及常见的 `2027届`、`本科及以上`、Go/Golang 和投递/关闭文本，不代表通用自然语言提取能力。

## 求职资料与简历草稿

「求职资料」包括基本条件、求职偏好、技能与项目。切换分区或打开简历导入弹窗会保留未保存编辑；离开或刷新前会提醒。保存求职资料时提交全部分区，保存项目表单则保留其他表单的编辑。默认仅在当前页面内存中保留未保存内容；手动项目编辑可按下文开启本机草稿。

教育经历按条目保存，可以同时保留本科与硕士的学历、专业、入学和毕业年份；用户选择一条作为本轮校招学历与届别。简历模型返回的教育经历、资料建议和项目事实默认全部勾选。可以修改或取消条目，保存时才确认提取准确并写入数据库；不再要求保存后重复确认同一条项目事实。

项目经历分别保存简介、完整 bullets 和匹配依据。简介与 bullets 按简历原文保留，换行不拆句，可以在项目卡片里编辑；新版整体分析会一起阅读这些完整叙述与已确认事实，不再只发送拆开的事实短句。解析默认按完整 bullet 提取一项成果，保留技术、实现机制与结果。模型仍拆成短句时，程序会在原文核对后将同一 bullet 的已实现内容合回完整依据；出现计划、否定、局限或混合类型时保留分开的引用，不扩大为已实现能力。项目名称不能独立证明能力，未勾选、未保存的简历草稿不参与匹配。已保存的完整叙述可以支持能力判断，但其中计划、否定和局限必须一起理解。

旧项目和事实继续可用；已有短句不会自动改写，因为数据库可能没有完整原文。可以重新导入简历，选择已有项目，补上简介、完整经历和新的匹配依据；同名项目复用、相同事实跳过，原有手工内容保留。项目简介最多 4000 字节，最多 20 条完整经历，每条与事实原文依据最多 2000 字节；模型字段继续核对脱敏原文，不保存文件或未审阅的原始简历。

项目事实区分 IMPLEMENTED、LIMITATION、PLANNED。保存确认不改变类型，计划和局限仍不能冒充已完成能力。重复导入复用同名项目并跳过完全相同的事实。手工添加事实也以保存作为确认动作。

在「技能与项目」展开项目后，可以删除整个项目，也可以展开某条事实后单独删除。删除前会要求确认；整项目删除会提示关联事实数量，项目与事实在同一事务中移除。其他项目和当前未保存的编辑保留。删除会改变匹配资料，相关旧分析显示待更新，历史报告仍保留；不会自动判断并清理相似事实。

文字版 PDF、DOCX、TXT 简历不超过 5 MB；浏览器使用随仓库打包的 PDF.js 和 JSZip 读取，不依赖运行时 CDN。扫描版 PDF 不支持 OCR。文件和原始文字不上传、不在后端保存。浏览器遮盖常见姓名标签、手机格式、邮箱、证件和链接；无标签姓名可以手动指定。自动遮盖可能漏项，外发预览需要用户完整检查。

用户确认后，只发送预览中的脱敏文字，最多 16,000 UTF-8 bytes。模型返回带原文摘录的草稿；程序核对摘录、字段和事实类型，再让用户选择保存。独立技能建议会过滤 goroutine、sync.Mutex 等实现细节，相关机制仍可保留在项目事实。草稿不自动写入资料。

「模型设置」提供 OpenAI 与 DeepSeek 预设，也可以使用服务器默认模型。具体预设以 web/models.js 为准。网页密钥按账号保存在当前浏览器 localStorage，未加密；调用时经 CampusTrace 转发给提供商，不写入数据库。退出后在同一浏览器重新登录仍可使用，也可以主动删除。调用配置不是队列或业务资料。

简历调用最多等待 90 秒，超时、密钥、余额、格式和摘录错误分别显示。原文可核对的有效条目会尽量保留，未通过的条目附固定原因。模型引用有效不等于推断一定正确，保存前仍需检查。

## 岗位雷达与本地初筛

登录后进入岗位雷达。支持按主投方向、公司、城市、岗位名称、分析状态和操作状态筛选；城市使用统一名称。可以选取筛选结果，批量忽略明显无关岗位；忽略可恢复，稍后看或已有投递记录的岗位不会被批量误移除。

初筛在本地完成，方向别名、语言任选、工作内容和技术线索用于缩小候选范围。初筛分仅供浏览，不代替模型阅读完整 JD，也不与深度分析的结论混算。学历、届别和招聘是否开放属于另行核对的条件；原文未给出要求不代表个人资料没有填写。

## 深度分析：先读完整材料，再给整体判断

新版使用 `holistic-v1`。输入包括已保存的资料字段、本科与硕士等教育经历、完整项目简介和 bullets、已确认的实现与局限，以及所选岗位完整 JD、名称、公司、地点和岗位类型。不发送简历文件、账号邮箱、联系方式、项目链接或模型密钥作为分析材料。未保存的编辑不参与分析。

每个岗位返回整体适配（值得优先考虑／相关，值得投递／相关性较弱／先核对资料）、核心工作、关键优势、差距、明确障碍、待确认问题和下一步准备。每类关键结论最多五项，引用对应的岗位和个人材料原文。引用只证明来源可追溯，不证明推断必然正确，仍需阅读结论与实践范围。

不再强制拆出所有原子要求，不按满足条数、技术名词数量或依据覆盖率打分。热爱技术、团队协作、自驱等泛化软性描述不影响适配或公司排序；材料没写不等于不会，领域不同也可以有可迁移经验。明确不符的硬性资格和需要学习的技术差距分别展示。学历、毕业范围等明确必需条件可以供本地资格核对；优先条件与复杂、不确定条件不能硬凑成资格门槛。

语言要求中的“如、等、至少一门、任意一种”按开放式示例理解，不能因为清单没列 Go 就判定不符；是否接受不明确时保留问题。工作职责、任职要求和培养安排分开：在指导下参与业务模块、容量评估或值守，不表示应届生入职前必须做过。报告区分“当前资料未体现”与本人明确不具备；长期行业意愿可以询问，不因简历没写而降低技术判断。Agent/RAG 应用经验与推荐建模、密码学研究与实际漏洞攻防分别讨论。同类后端岗位优先比较实际工作、项目迁移和准备成本。

点击深度分析后先核对完整脱敏预览，再确认发送。普通分析按最多三个岗位一批执行，单个 JD 最多 24,000 字节，候选资料最多 64,000 字节，每批整体输入最多 96,000 字节；全部按 UTF-8 字节计，不截断项目或 JD。超过限制时明确提示缩小候选范围或整理重复资料。

旧版逐项报告继续留在详情里作为历史参考；主列表标记“旧版分析参考”，可以重新整体分析。旧技术分与投递优先度不作为新版整体适配或公司排名。

## 同公司比较：决定有限名额投给谁

侧栏的“公司投递决策”把本次首选与备选、完整比较理由、截止时间、已选岗位和限投名额放在一页。可搜索岗位名称或城市，勾选最多 16 个候选，点击“查看所选岗位”后才更新范围。超过 200 个本地岗位的公司先选择候选范围；不静默截取前 200 个。查看资料不调用模型；生成比较复用原有外发预览和持久分析任务。

名额按本人已确认的招聘批次规则统计，只约束规则内的岗位。缩小比较范围不会清空范围外计划或已投记录。名额与投递、当前截止证据在同一只读事务中读取；创建计划时仍在写事务内重新检查。排名不自动创建计划，需点击“加入投递计划”并确认。官网未给出可靠截止时间时显示“截止时间未明确”，不能把缺少时间理解成长期开放。

点击“同公司对比”，选择全部本地岗位、当前筛选结果或已选岗位范围，再查看。读取报告不调用模型。没有本次范围报告时，点击“核对并生成整体比较”，检查完整资料后发起独立任务；**无需先完成每个岗位的深度分析**。

模型会同时阅读候选岗位的完整 JD 和同一份完整个人材料，给出首选、备选、并列分组、相对优势与取舍，不拼接单岗分数。每次最多 16 个岗位、完整输入最多 128,000 字节；范围过大请先缩小候选集，不默默截掉岗位。查看本地范围最多 200 个岗位，响应最多 2 MiB。

单岗报告和公司比较分别保存。公司报告绑定精确岗位集合、完整资料、岗位文字及元数据、模型和指令版本。增加或移除候选岗位、改资料或 JD 后，原比较不作为新范围结论。相同输入复用缓存；结论仅针对报告列出的候选岗位，不代表官网所有岗位或录用概率，实际限投规则仍按官网确认。

## 持久任务、配额与恢复

复用现有 MySQL、Redis 和任务执行器，没有新增中间件。MySQL 保存任务、阶段、诊断和报告，Redis 控制账号执行锁，模型请求前原子扣减每日调用预算。密钥和本轮补充遮盖姓名只在执行内存中；任务表只保存岗位编号、资料与输入哈希、范围和状态。

任务包含普通分析和 `COMPANY` 公司比较两种类型。关闭页面后已授权轮次继续运行；进程中断不会自动恢复密钥或再次付费调用，继续与失败重试前需要重新核对。公司比较整体失败时重试同一完整范围，单岗已有报告不会使公司失败项消失。公司任务完成后可点击“查看本轮公司比较”。

提交结果时重新核对完整输入与执行版本。资料、JD、元数据变动或任务被取消后，迟到的模型结果不能覆盖当前报告。缓存命中不扣模型调用；失败或超时尝试计入预算。模型原始答案、完整简历和密钥不写入任务日志，只记录固定失败原因、范围、阶段与请求编号。

## 导出给 ChatGPT，再导入结果

选取岗位后点击“导出到 ChatGPT”。服务只准备脱敏快照，不调用模型。浏览器展示完整分析包，检查后下载 Markdown 或 ZIP，再自行上传聊天。每次导出最多 1,000 个岗位、5 MB；每包最多八个岗位、约 48 KB，过长单岗独立成包并保留完整文字。优先将同公司候选放在一起。公司完整范围跨包时不生成局部公司排序；可另选少量候选生成同包比较。

新版分析包为 `campustrace-chat-v4`，指令版本 `reviewed-candidate-2026-10-09`。返回 `jobs[].assessment`；包内完整的 `company_inputs` 可另返回 `comparisons`，包含相对排名与关键引用。分析包已提供编号、输入标识、完整项目和 JSON 示例，无需聊天生成逐项分数。

点击“导入聊天分析”，上传一个或多个 JSON，或粘贴完整 JSON。每次最多 100 个岗位、2 MiB，多文件必须来自同一候选资料快照。程序在本地核对权限、输入身份、结果结构和关键引用，不要求拆分复合能力、覆盖每句 JD 或返回每项匹配。旧版 v3 结果仍接受为历史逐项报告，前提是当前资料与岗位绑定能核对。

预览列出每个岗位的结果与问题；有效岗位可以先确认保存，失败岗位保留原有分析。公司比较范围或引用有问题时单独提示，不阻止有效单岗导入。确认键绑定完整提交文档、通过子集与已有结果版本，修改 JSON 或资料后必须重新预览；通过子集和有效公司报告在同一事务保存，避免未经确认的部分写入。

导出时补充遮盖姓名的，导入需填相同称呼。只保存遮盖后的结论与资料上下文哈希，重开页面仍可读取已接受结果，不保存补充姓名。聊天导入不调用模型或消耗 API 预算。ChatGPT 聊天套餐与外部 API 账单分别处理。

## 分析后的准备与 Agent

岗位详情的“准备清单”直接把整体报告的下一步建议变成可勾选行动；历史面试复盘单独展示，不伪装成本岗位缺口。勾选只保存当前浏览器的任务编号及报告版本，资料或报告改变后不沿用旧进度，不修改技能或投递记录。

求职问答 Agent 读取已有整体报告与公司排序，给出简短说明。没有可复用的公司报告时提示回岗位雷达生成，不能从单岗结论或旧版数字擅自拼出排序。读取报告、准备清单与 Agent 工具本身不触发深度分析；Agent 对话仍可能使用其单独配置的对话模型。

接口继续使用 `POST /api/matching/tasks`（公司任务带 `kind=COMPANY`、`company`、`scope_key`）、`POST /api/matching/company`、`POST /api/matching/preparation/{id}` 和聊天 export/import 接口。公司报告新增 `company_match_reports`，数据库迁移为 `009_holistic_matching.sql`。

## 今日待办与岗位操作状态

「今日待办」优先展示待处理事项：未来 7 天内有可信截止时间的未投递计划、未来 7 天的未完成面试、已记录完成但尚无复盘的面试，以及最新尝试仍然失败的深度分析岗位。截止计划先排，随后按面试、复盘和失败项展示；截止和面试按时间从近到远排列，复盘和失败按最近时间排列。每类展示前 5 项并标出完整分类数量，更多可进入对应工作流页面。查看、分类与刷新待办只读取本地服务的数据，不调用模型；跳转失败任务后仍需要用户核对外发资料才能重试。后续任务已经替代的旧失败、已取消任务、后续同步分析已成功的旧失败不再提醒。岗位发现与变化保留在下方折叠区；该区暂不可用时不影响单独读取待办。

「岗位雷达」增加独立的操作状态筛选，可与公司、城市、分析状态、初筛建议组合：未处理、稍后看、已计划、已投递、已忽略和已结束。已投递包含实际提交后拒绝或撤回的历史记录；尚未投递就撤回的计划归入已结束，不计为已投递。稍后看／忽略是独立标记，可与投递阶段并存。列表显示具体投递阶段与标记，返回页面后保留操作状态筛选。工作流元数据按当前账号和岗位可见性关联，只包含编号、阶段、版本和投递时间，不携带投递备注或简历名称，也不改变候选资料与分析缓存身份。

## 投递、面试与准备上下文

「投递进展」按公司和岗位名称展示记录，附投递时间、所用简历版本、最近更新时间与投递备注。支持搜索公司／岗位、按公司与阶段组合筛选；进行中的记录直接展示，OFFER／REJECTED／WITHDRAWN 记录默认折叠，筛选时展开匹配的结束记录。两组各按每页 25 条浏览，从岗位或面试进入具体申请时会定位对应页并展开结束记录。接口最多返回最近更新的 500 条投递，达到上限时页面明确提示载入范围。展开「更新进展与投递资料」可分别更新阶段及本次进展说明、编辑简历版本和备注；资料编辑同样校验版本并保留事件，不改变阶段或投递时间。有效的官方来源提供招聘官网入口，手动来源和不可安全打开的链接不会标为官网。仍可进入岗位准备清单、面试安排和进展历史；旧记录缺少资料时明确显示尚未记录。

当前深度分析的「逐项依据」与准备清单中，能力项的「暂无依据」可点击「补充项目依据」。页面并排展示岗位原文与填写表单：选择已有项目或新建项目，填写本人实际完成的工作、实现方法、结果及范围，可添加个人依据位置；岗位文字不会自动写入个人事实。用户核对后保存为已确认的 `IMPLEMENTED` 项目事实，输入变化会令旧分析待更新。保存不调用模型；随后可点击「核对外发资料并更新本岗位分析」，重新核对完整外发资料并确认后，才分析该岗位。过期分析和投递资格项不提供这个补充入口。

投递按 `PLANNED → APPLIED → OA / INTERVIEW → HR / OFFER` 及允许的拒绝/撤回路径流转。一次状态变更在同一个 MySQL 事务中锁定并验证当前状态、校验 expected version、插入事件并更新记录；1.0 不支持重新打开终态投递。

面试和复盘归属于对应投递的用户。「面试与复盘」展示公司、岗位、地点与轮次，支持公司／岗位搜索、公司筛选，以及待面试／待记录完成、待复盘、已完成分类，每页 25 轮。接口最多返回最近安排的 500 轮，并在达到上限时显示载入范围；岗位信息按当前可见性校验，复盘按同一账号关联。未填写结果的新面试默认 PENDING，但只有显式记录完成情况才设置 finished_at；“已完成，等待反馈”属于已完成，可进入待复盘列表。完成时间表示首次记录完成情况的时间，后来补录 PASS／FAIL 反馈不会改写这个时间，也不自动推进投递阶段。安排、复盘及面试卡片均保留公司／岗位上下文，可返回对应投递或准备清单。复盘为追加记录，每次面试一份；经验证的显式薄弱知识点累积次数、严重程度、首次/最近出现时间与复盘引用。Agent 工具与旧准备上下文接口使用与 Eligibility/GoFit 相同的输入快照，展示 `current_requirements`、`current_observations`、已核验项目事实及限制、薄弱知识点和检索知识，不混入历史要求。历史薄弱点优先级为严重程度 × 出现次数；页面的岗位准备清单使用上面的最新深度分析依据。

同公司对比使用投递优先度辅助决定先投哪个：核心 DIRECT/PARTIAL/TRANSFERABLE 分别计 1/0.75/0.6（比原有核心分更重视相关经历），明确不符合计 0，未知项暂按中性值 0.5；分母为全部核心技术单位。参考区间将未知项按 0 到 1 计算，表示资料缺口的影响，并非统计置信区间。低覆盖岗位有相关核心依据也能参与排序；只有软性要求、没有相关核心依据、分析过期、关闭或明确不符合投递资格时不推荐。资格未知只提醒核对，不能直接当成不可投。原有核心匹配分仍按已知项计算，与投递优先度分开展示。

Agent/RAG 明确并列的子能力保持各自原文程度，同一概括项已被完整子项覆盖时不重复计分。聊天结果摘录过短时从唯一来源补全上下文；若恢复了更高程度要求，将原先直接匹配保留为部分匹配并提醒核对，不要求整批重新生成。

实际使用/搭建/开发经验仅引用技能标签时，保留部分匹配并标记实践待确认；引用意向或项目局限证明能力仍撤销。新分析与新导入使用修订后的核对规则，旧结果标为待更新，历史报告保留；不会自动发起模型请求。

聊天导入会忽略被模型误列为要求的独立章节标题（如“专业能力：”），仅限原文及连续摘录中均有完整标题行、没有条件值或选择分组、且对应唯一的“暂无依据”空引用结论。摘录可以包含前一句原文，但 text 必须只有标题。真正的专业、学历或技术条件仍保留；标题后有实际内容、标题被赋值或引用成肯定依据时仍要求核对。预览和报告显示忽略数量，其后的错误序号仍对应原 JSON，避免定位偏移。

明确的“专业不限”若漏填专业值，会从对应连续原文补为“不限”，保留条目并按不设专业门槛展示；其他缺失专业值不推测补齐。

已有独立软性条目且类别、原文摘录完全一致时，技术条目会去掉重复的纯协作等描述，保留自身结论和完整摘录；不会把一个技术结论复制给多个新能力。缺少独立软性条目、来源不同或真正同时要求多项独立技术能力时，仍要求分别判断。

若模型把任职条件误标为未来职责，导入会依据原文明确的“工作要求／任职要求／加分项”分段校正分类，并显示校正数量。明确的学历、毕业届别等保留为资格条件；缺少结构化值的部分仍待人工核对，不计技术分。引用跨越不同分段、同一句出现在职责和要求两处、原文没有明确分段或带任选分组时不自动改分类。通用的“掌握至少一种/一门岗位列举的主流编程语言”与同源的明确语言任选条件同时存在时，保留明确条目及它自己的结论，避免重复计分；删除概括项之前仍核对其引用。


基础能力自评维护在求职资料的“技能与项目”中：数据结构、算法、操作系统、计算机网络、数据库基础、计算机系统结构分别选择了解、熟悉或有实践，留空不表示不具备。后端校验主题、等级、重复与数量，按固定顺序保存到现有 profile JSON；旧客户端省略字段时保留原值，显式空列表可清空，仍遵守资料 revision 的并发检查。自评作为 `foundation-` 开头的 SKILL 事实参与初筛、API 比较与聊天导出；不生成 IMPLEMENTED 事实。自评低于岗位要求的程度时，直接匹配会在本地降为部分匹配；仅有自评的实际经验也保持实践待确认。更新自评会改变候选人及能力比较身份，旧分析需要更新，旧聊天包需要重新导出。

纯软性要求在投递界面默认不限制投递，不改写模型的原始结论或制造个人引用。它们仍不计技术分与投递优先度，在报告及准备清单中默认折叠为可选面试事例。具体日志、监控、工程排障等技术能力继续单独比较；学历、届别等 QUALIFICATION 即使被误标 SOFT 也不作为默认放行项。

岗位雷达默认按投递优先度查看已分析岗位，保留核心技术评分在详细报告中。首页的公司内技术排序只使用当前账号本地已分析、具备核心相关依据且未关闭、未忽略的岗位，按方向、投递优先度、覆盖度、城市与类型偏好、加分项排序，保留并列并标出待分析数量。它使用摘要计算，不读取完整个人引用、不新增模型调用，也不代替资格核对；正式同公司对比继续核对当前投递资格。界面分别展示资料待核对、引用待修正、实践待确认、程度待确认和明确不符合，不把未知技术项直接当作不符合。


## 已核对资料正文

当前整体分析使用 `candidate.document`：从已保存资料组成完整文字，保留多段教育经历、项目描述和要点原文，补充经历可用于遗漏的实习或科研；偏好单独标注为非能力证据。外发不再附一套重复的 facts/projects JSON。内部原始依据映射仍用于引用核对和权限验证。指令版本变化使旧上下文不复用，旧分析包需重新导出，不自动重新调用模型。入口与记忆、练习说明见 [agent-workspace.md](agent-workspace.md)。

## 在岗位雷达里做公司取舍

岗位雷达上方可以切换“岗位列表”和“公司投递决策”。前者用于收集、筛选与批量分析，后者用于给同一家公司挑候选岗位、查看比较和安排投递计划。旧的公司决策入口仍可打开，会进入岗位雷达的公司视图。

公司视图显示已有深度分析结论，可以按分析状态、整体适配、城市筛选，也可以按深度分析、旧版技术分或初筛分排序。“按当前排序补选”会保留原有勾选，补选前 4、8 或 16 个可用岗位；每次公司比较最多 16 个。新版整体分析没有百分制分数，优先／相关等结论与旧版数值分开排序。过期分析不作为当前分数。

勾选与岗位列表共用，并在当前浏览器会话内按账号保存。公司、搜索、筛选、分页和候选范围会分别记住；过滤掉一个岗位不会取消勾选。查看岗位和准备清单直接打开详情，关闭后继续当前筛选。勾选只改变候选清单，“查看所选岗位”才更新比较范围，加入投递计划仍需确认并由服务端检查名额。

列表读取只构建当前初筛摘要，不逐岗返回完整技术证据；打开详情时再读取完整依据。任务进度与岗位摘要并行读取，不再为了进入列表自动读取第一份岗位详情。进入公司视图时只读取这一家公司的候选摘要。所有这些浏览操作都不调用外部模型。

岗位摘要先显示，分析任务进度随后更新；等待进度期间仍可搜索、筛选、翻页和勾选，进度回来后保留这些操作。读取任务失败时有独立的重读按钮。在任务状态确认前暂不启用分析、导入和批量修改，避免把仍在运行的任务当作已结束。公司视图复用刚读到的账号能力设置，减少重复请求。

库存卡片只传输排序、筛选、状态与一条初筛说明，完整候选材料在核对外发时从导出接口读取。后端缓存本地初筛摘要，按账号、完整资料身份、个人条件、岗位输入与初筛版本区分，最多 10,000 项／32 MiB 估算预算。未命中时最多四个计算并行；每次读取仍核对当前可见性、最新观察、收藏／忽略、投递记录和报告身份。修改资料或岗位后不会用旧摘要决定新分数，失败观察也不会借旧的成功原文继续分析。

公司候选页会记住快速勾选的数量，切换筛选后仍按你选择的 4、8 或 16 个补选。桌面长列表勾选后，操作区会停留在视线内；小屏幕则顺着页面排布，避免遮住岗位。比较报告先显示每个岗位的排序理由，展开“优势、取舍与依据”再看细节。展开状态在页面内刷新时保留。

## 用 GPT 聊天比较，再把排序带回来

在岗位雷达的“公司投递决策”里选好同公司候选，点击“用 GPT 聊天比较”。可以额外填写要遮盖的姓名；预览包内完整文字后，点击“下载给 GPT”，把 Markdown 文件上传到 GPT 聊天。包里包含本人已核对的完整资料、每份完整 JD 和返回格式，不包含原始简历文件、API 密钥、已有模型排名或人工参考答案。没有单岗深度分析也可以直接比较；每次最多 16 个岗位，保留完整文字，不截断超限内容。

让 GPT 返回一个 JSON 文件或单个 JSON 代码块，再在同一入口选择文件或粘贴，点击“预览返回结果”。预览按排名展示理由、相对优势、取舍、引用和待确认问题；核对后点击“确认保存公司比较”。无需 API 密钥，导出和导入不调用模型，也不要求重复生成单岗 assessment。

回传使用 `campustrace-company-chat-v1`，绑定指令版本、候选资料、完整岗位集合与原文；允许并列，拒绝漏岗、重复岗位、跨公司或无效引用。PDF 换行等格式差异可恢复为对应连续原文，不能改写或拼接内容。确认时重新检查权限、输入和已有聊天比较版本，旧预览不能覆盖并发更新。资料或 JD 变化后重新导出；手工遮盖名称需在导入时保持一致。

保存只更新这组公司排序，保留已有单岗报告与人工评测标注。公司视图显示当前范围最新的 API 或聊天比较，并注明来源；切换范围不会套用另一组岗位的排名。指令升级后旧比较保留在数据库，当前视图不复用，也不会自动调用模型。评测 JSON 仍是独立的人工标注入口，GPT 返回内容不自动当作人工答案。

## 筛选、翻页与批量操作

岗位列表保留覆盖全库存的轻量索引，排序和“选择全部结果”不会只作用于当前页。每页读取 50 张卡片的说明，完整原文和匹配依据在详情中读取。任务进度单独加载，读取失败仍可浏览与勾选。刷新只更新变化的索引条目；回到列表也复用当前浏览会话中的索引，再向服务核对版本。

“关键词、多地点与筛选预设”里可以选择包含全部或任一关键词、排除关键词，以及同时勾选多个地点。地点按任一符合处理；使用上方单地点选择会替换多地点条件。选好条件后，填写预设名称并保存，下次从“常用筛选”直接切换；同名保存会更新原预设，最多 20 个。预设按账号保存在本机浏览器，不包含简历、模型密钥、已选岗位或外发许可。

批量操作栏默认只显示选择摘要，点击“展开操作”再分析、导出或忽略。“撤销刚才的忽略”恢复上一次批量操作实际更新的岗位，保留原本已忽略、收藏和已有投递的岗位；失败时保留尚未确认完成的部分。撤销入口在当前浏览会话内有效，之后仍可从“已忽略”手动恢复。

投递进展、面试与复盘会按账号记住筛选、页码和滚动位置。离开再返回时恢复；从某条岗位或待办直接进入，则优先展示目标记录。未保存的表单内容默认只留在页面内存，离开前会提示，不写入浏览状态。复盘编辑可自愿开启独立的本机草稿。


## 编辑草稿与页面加载

初始页面仅加载登录、导航和基础显示组件，其余页面代码与样式按需读取。DOCX 读取及多文件 ZIP 导出所需的文件库在使用时加载，读取失败可重试。

「求职资料」可以自愿开启本机草稿，保留手动新增与编辑项目的未保存内容；「面试复盘」支持复盘文字和待加强知识点草稿。默认关闭，按账号和记录隔离，保存时间为七天。原始简历、简历解析导入草稿、个人联系方式、模型密钥和外发确认不在此草稿范围内。求职条件仍需正式保存。

刷新或重开编辑页面后，可手动恢复草稿。程序先核对记录基线和当前编辑，已有记录或当前文字变化时不覆盖；可下载旧草稿自行核对。恢复内容须正式保存才进入业务记录。正式保存后清除已保存部分，保存期间新输入的编辑保留。退出登录不会删除已启用的本机草稿，同账号再次登录仍可恢复。
