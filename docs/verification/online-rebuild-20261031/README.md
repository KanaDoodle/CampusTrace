# 2026-10-31 Search 在线重建验收

本轮基线为 `c3a630f`，目标为同一工作分支中的在线重建实现。所有数据来自独占合成测试环境；没有读取个人业务库、浏览器密钥或调用外部模型。源码摘要、检查清单与精简结果随本报告保存，原始日志位于忽略目录 `bin/verification/online-rebuild-20261031/`。

## 能复现的功能证据

`make online-rebuild-test` 使用真实 MySQL 8.4、Redis 7.4、etcd 3.6.7、OpenSearch 3.9.0，以及独立 Go Search/Worker 子进程，以 race 构建运行。没有用内存假索引替代真实存储。

| 场景 | 实际检查 |
| --- | --- |
| 回填第二批被网络代理阻塞 | 已保存 64 份投影游标；旧索引的完整全文结果继续可读 |
| 阻塞期间提交十次资料更新 | 数据库正常提交，独立的前台同步追平十份变更，候选仍被阻塞 |
| Search 与 Worker 分别 SIGKILL | 两个实际进程被终止；恢复后继续相同操作与游标，未重置活动索引 |
| 停机期间更新、新增、运维删除后对账 | 权威回退保留正确结果；恢复后投影与墓碑追平，最终可见岗位仍为 131 |
| alias 已变更、确认回复被代理丢弃 | 远端停在 CUTTING、Core 保留源代次；确认恢复前仍可全文读取完整结果 |
| 无业务变化的两个暂停窗口 | 共 24 次全文读取，没有基础回退；这不是全程负载测试或可用性统计 |
| 追平后回滚 | 旧索引先接收新的更新、投影与墓碑，确认完成后才重新激活 |
| 私有岗位与其他账号 | 新旧代次均复核 Core ACL，其他账号无法读到私有结果 |
| 并发创建任务与候选同名重建 | CAS 只受理同一操作；候选 UUID 改变时拒绝继续，不切换活动索引 |
| 候选数量不变但哈希错误 | VERIFY 阶段拒绝冲突，旧索引仍完整可读，可取消并重新开始 |
| 查询结果已读取、随后发生切换 | 在同一业务版本的完成交接证据下仍返回全文结果；真实数据变更继续触发权威回退 |
| 已排队的旧阶段更新失去连接锁 | 用真实行锁制造等待，再 KILL 锁连接；旧更新不能覆盖后续 CATCHUP 进度 |

其中运维删除是显式测试对账路径，并非项目提供了新的岗位删除 API。暂停窗口的 24 次读不能解释成生产 SLA；十次写入耗时只是该次诊断，不是系统最大吞吐。证据 JSON 记录这些范围。

## 确认与安全边界

正常投影发布和回填 I/O 在事务外；最终激活使用有 1.2 秒预算的 SQL 写屏障。别名切换与 MySQL 提交之间没有跨存储原子事务。远端阶段和 SQL 检查点分别持久化，保留源读路径来恢复不确定结果。

源码通过物理 UUID、事务增量、逐份可见性校验、按操作/阶段条件更新和提交确认实现上述行为。未声称单节点部署具备高可用、任意人工索引篡改都能检测，或在线任务可以在数据库换代后自动接管。旧版写入进程必须先退出；重建需要额外磁盘，尚未自动清理旧索引。

## 回归与性能口径

原有 Search 查询、故障隔离、Kafka 独立消费与通知、数据库备份恢复和公开 KanaRPC 依赖边界均需要回归。原始执行记录区分修改前的阶段性检查与最终源码检查；性能实验在其他测试容器退出后依次运行。

k6 对照使用同一版实验脚本、同机、相同容器配额和请求负载。基线采用旧式空索引替换，候选采用在线重建。该阶段比较全文/回退请求数及真实切换完成状态；不把两种模式的混合延迟作为同一种性能指标。稳定全文与停机回退阶段才使用原有分位数门槛。实验只代表记录条件，不是生产容量。

实现和操作说明见 [在线重建](../../search-service.md)，面试讲解入口见 [工程证据](../../engineering-evidence.md)。

## 最终结果

- 5 个真实在线重建用例通过；原有 7 个 Search 用例、Kafka/通知专项、79 表/75 引用的 CLI 恢复、公开模块构建、vet、全包 race、437 项前端检查与依赖边界通过。集成测试由独占脚本另行以 race 运行，未开启环境的默认全包测试会跳过这些用例。
- 实际 Kafka 容器栈中在线操作到达 `DONE`，5 次静态全文轮询无基础回退；重建面板 8 项、原有 Search 9 项及故障隔离 6 项均通过读取检查。既有事件链路、通知去重与五类服务追踪继续通过。
- 同机、同一版 k6 脚本，1,000 个目录岗位加 1 个写入岗位、10 次查询/秒、每阶段 15 秒：旧式重建 150 次查询中 85 次基础回退；在线重建 151 次查询全部全文、0 次基础回退，操作代次变更和 `DONE` 均已核对。
- 稳态全文 P95：基线 14.302 ms，候选 13.716 ms；P99：15.495 / 14.382 ms。停机回退 P95：7.428 / 5.956 ms；P99：202.821 / 203.361 ms。四项分位数均通过原有 `旧值×1.5+25ms` 门槛；没有据此宣称最大吞吐或统计显著提速。

`performance-comparison.json` 保留实际环境、负载、源码快照身份、请求数和分位数。在线模式的历史字段 `recovery_wait_seconds_after_load` 仅记录确认重建完成后的最后一次全文就绪等待，不用于总重建耗时或 RTO。

在最终独立源码中补跑完整数据库回归：181 个集成顶层用例通过、17 个跳过，连同 pipeline / scheduling / recruitmentmail 总计 205 个顶层用例通过，均启用 race。Kafka/OpenSearch 的额外依赖用例已另行实际运行。合回已有工作区后，构建、全包 race、445 项前端检查、5 项在线重建及 Kafka/CLI 恢复专项再次通过；其他 Agent 改动保留在工作区，不包含在本次提交中。
