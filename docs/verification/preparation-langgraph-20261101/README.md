## 真实跨进程边界

[完整检查列表](acceptance-result.json)、[业务回执](acceptance-business-receipt.json)、[重启前文件检查点](acceptance-checkpoint-restart.json)、[澄清中断关联](acceptance-clarification-checkpoint.json)。

- 预览零调用；缺少用户确认不启动；启动请求幂等；其他账号不可读取或使用本申请。
- 确认后 MySQL `saved_at` 非空，SQL 回执与 HTTP 回执一致、重复确认唯一；资料变化后确认返回 409，SQL 中没有保存时间和新增回执。
- Python 不可用时返回具体服务错误，不创建表面成功的任务、不回退旧 Go 循环。
- 用只存在于验收脚本中的回调代理丢弃一次 **Go 已持久化的模型响应**。Python 留在模型节点；继续后复用该回执，没有重复模型请求。
- 单独强杀 Python 时，上游模型收到取消，Go 保留 UNKNOWN。未确认重试返回 409 且零新增调用；确认后只追加一次尝试，已完成读取不重放、未知预算占用不丢失。
- 后续也重启 Go，并仅在自有数据库注入租约过期。这里的“租约过期”是故障注入，不是等待 60 秒的耗时测量。
- 时间/天数缺失产生实际 LangGraph 中断；补充 15 分钟后，新版计划总时长不超预算。父图通过 `Command` 关联子修订后结束。
- 浏览器从申请档案自然入口操作，反馈“已掌握 Go 并发、只剩一小时”后排除该项，显式保存并刷新读取。取消传播到模型，旧任务无法保存。

这些故障在合成材料及可控 HTTP 服务上注入，验证程序收敛，不估计线上故障概率或提供商处理/收费状态。

## Badcase 与本轮修复

1. 拆成受控单步时，重复来源分支曾提前返回，原有去重测试立即失败；恢复分支内继续处理后通过回归。保留两次读取观察，模型上下文只加入新正文。
2. 仅收到 Python 的 200 不能代表 Go 已完成业务：新增协议校验，图成功但缺少 Go 最终回执时失败，不形成可保存结果；SQL 检查点写失败也不返回单步成功。
3. 扩展验收在同账号超过每分钟五次启动/恢复，被 503 正确拦截。测试改用独立账号及其本人岗位，不放宽产品限流；初次复用其他账号岗位的 404 也保持拒绝。
4. 直接 SQL 比对起初使用 MySQL CLI 默认字符集，中文显示问号；改为显式 utf8mb4 和原始 JSON 输出。API 及库内中文无损，问题在验收客户端编码，未修改业务数据来适配断言。
5. 澄清界面原来只能直接补充分钟；本轮增加天数输入并纳入下一版审阅，避免用户在另一个表单中寻找约束字段。
