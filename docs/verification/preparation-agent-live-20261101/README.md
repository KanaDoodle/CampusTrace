# 申请准备 Agent：真实模型调试记录

2026-11-01，沿用用户明确授权的 CampusTrace 网页模型配置，调用 `https://api.deepseek.com/chat/completions` 的 `deepseek-flash`。本轮共 **17 次真实请求、44,621 个提供商报告的 Token**，在 24 次请求上限内结束。材料全部来自仓库已有合成调试任务，没有发送个人简历、JD、复盘或账号业务数据。

已有能力可以完成有来源的三小时准备计划；首次调整任务暴露失败，修改后的一次复测生成了剩余计划。小样本尚未证明动态方案整体优于单次生成。

## 方法与配置

- 数据：[原始 24 个任务](../../../internal/agent/testdata/preparation-tasks.json)，SHA-256 为 `c94724634e3650aa16583ecea0d0960a7a17b13bd1de7391218915598bce8507`。只选择 `development` 的三个任务，18 个保留案例未调用真实模型。
- 三组按相同目标、材料允许范围和 128,000 Token 估计预算运行；每组总时限 35 秒，上游 HTTP 时限 25 秒。各案例顺序为单次生成、固定检索加综合、动态调用，未随机化。
- 单次生成获得整个小规模允许语料；固定方案用旧 `preparationQuery` 与 BM25 做一次检索；动态方案初始只有冻结材料，可选择最多三次查询、最多六次模型请求。工具读取使用合成语料上的真实 BM25；模型返回来自真实上游。
- 请求使用现有 ChatClient：`temperature=0`，DeepSeek `thinking=disabled`。记录的是请求模型别名，未独立核对提供商内部模型修订版。
- 浏览器通过原本本机地址的临时评测页面，复用唯一账号的现有模型选择；密钥经同源请求交给本机子进程内存，不写报告、命令参数或密钥文件。临时服务不读取业务数据库；结束后停止。
- CLI 全部只读，业务写入为 0。确认、权限、版本和幂等的 SQL/API 证据仍见[独立程序验收](../preparation-agent-20261101/README.md)。

## 修复与同材料复测

针对生成约束与失败可审阅性做了以下修改：

1. 工具 schema 显示实际天数、剩余分钟及仍可选择的项目 ID、标题和依据类型；程序继续核对字段配对和总时长。
2. 计划被拒时，反馈具体条目及引用、依据或字段校验原因；无效调用格式进入失败轨迹。
3. 评测记录实际模型返回参数、被拒候选、失败原因与 usage；单次生成和固定方案使用与循环一致的严格 JSON 与澄清校验。
4. 修正评测器输出上限：初版 `limitedModel` 包装隐藏了 `LiveModel`，报告虽标记 2048，实际请求未携带该上限。现于包装前设置 `OutputTokenLimit=2048`，请求级测试验证该字段。初始报告原样保留，不能作为严格的 2048 输出预算对照。

仅复测已经用于调试的一小时调整任务，新增四次请求。各组使用相同的新约束和显式输出上限。

| 方案 | 程序结果 | 模型请求 | 总 Token | 耗时 | 文本审阅观察 |
| --- | --- | --- | --- | --- | --- |
| 单次生成 | 通过，MySQL 60 分钟 | 1 | 2,667 | 3.66 秒 | 仍把 10 分钟 Go 取消复习塞进 MySQL 项，违反已掌握反馈 |
| 固定检索加综合 | 通过，MySQL 60 分钟 | 1 | 2,520 | 3.36 秒 | 跳过 Go；产物中多余地重复了材料未提供的 PLANNED 标签 |

这次复测说明，公开程序已知的选择约束有助于模型输出可接受计划，同时保留了模型选择查询与组织内容的空间。修改包含 schema、错误反馈和评测器修正，且只复测一次，不能单独归因于某一处修改或推导统计成功率。

## 语义审阅与下一步

[逐项审阅](semantic-review.json)由本轮代码助手完成，不是独立人工标签。程序通过只说明时间、项目身份和逐字引用等约束满足；不能证明每条建议在语义上使用了正确依据，也不能防止已掌握主题换个标题再次出现。原合成父计划的 MySQL 项甚至引用了 Go 并发片段；数据原样保留，暴露了逐字绑定与语义支持的区别。

本轮没有个人真实求职材料、复杂长材料、保留集真实模型效果、真实业务写入效果或重复试验结论。所有已返回请求都有 usage；未提供授权单价，费用为 `null`，未用 Token 数推算账单。
