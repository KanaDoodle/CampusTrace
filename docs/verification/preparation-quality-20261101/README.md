- 新引用要说明支持点；提示排除装饰性引文，界面同时显示原句与关联说明。程序校验解释存在、长度、敏感内容及原引用绑定，语义支持仍由审阅判断。
- 新任务声明类型、数量与产物范围。代码单元至少30分钟，35分钟3个编码单元被拒绝；scope显式数量与units不一致被拒绝。15分钟最多两个ORAL/READ单元，反馈一次列出全部工作量冲突。
- 检索有缺口及预期用途，短任务最多一次，连续两次没有新来源则停止；off模式不提供工具，也不允许受控接口越过。完整回执使用Go步骤号而非模型call ID关联。
- 旧计划保持兼容；用户确认、引用来源、版本、幂等、取消及UNKNOWN机制保留。
- 本机配置0600且Git忽略，正常启动可读取；Compose API获得配置，Python服务没有模型Key。[配置检查](model-config-proof.json)只保存安全元数据。

## 剩余语义边界

已知口号引用在本轮新输出中未再出现，但supports仍由模型生成，不能当作蕴含证明。显式数量规则减少了可识别的超量安排，自然语言仍可能把多个关联主题写成一个问题；短时计划的隐含复杂度和个人实际完成时间仍需审阅。缺简历初版的一项叙述修改被标为MODIFY，类型语义不够贴切，记录保留。

下一优先项是在新的明确额度下，复核正常任务auto/off是否增加有效信息，并以少量用户实际完成记录校准练习时间门槛；本轮不新增评审模型或扩大评测平台。
