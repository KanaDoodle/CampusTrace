# 面试准备 Agent：一致输入回归与引用纠错

2026-11-01，沿用已授权的 DeepSeek Flash、脱敏材料快照和执行预算，补跑之前未完成的动态验证，并修复引用错误反馈与内部 ID 契约遗漏。本轮共 **101 次真实请求、894,229 个提供商报告的 Token**，未用满 120 次上限。

完整模型返回、失败候选和准备样例保存在仓库外的私有目录；本目录只包含统计、源码哈希和测试记录。上一轮数据与失败没有覆盖。

## 输入和方法

- 使用同一份脱敏简历、三份归档真实 JD、两个项目 README 节选和五段学习资料。用户没有真实面试复盘，不提供 HISTORY 材料。
- 七项任务的旧目标文字已与数值时间对齐，材料正文未改。新文件 SHA-256 为 `941ee0b0f07a8ed9ca7ed08ed2d0e309f6a01211d1059a39ca9a26f07e1c0263`。
- 这些案例已经参与上一轮调试，本轮是回归，不是新的盲测。也不能把旧输入下的 12/18 与新输入下的结果直接归因于某一处代码修改。
- 每组共享模型、允许材料范围、128,000 准入估计预算、2048 输出 Token 上限和 35 秒时限。单次方案获得全部小规模允许语料，固定方案检索一次，动态方案可按中间结果选择后续动作。
- 三组按单次、固定、动态顺序串行运行；调用次数和 Token 是实际回执，耗时不是生产容量或随机化延迟对照。未提供授权单价，不估算账单。

## 实际发现与修改

### 引用文字正确，却关联到了错误材料

v4 在一致输入下的 15 分钟动态任务仍失败：一段来自简历的测量描述被挂到了项目 README。程序正确拒绝，但原反馈只说引用不匹配，模型反复提交同一错误并出现无效 JSON。

新增 `preparationReferenceError` 标记具体条目与引用位置。`preparationPlanRepair` 仅在本次执行已读来源中查找逐字匹配，给出至多四个来源候选，保留类型、标题和申请范围；由模型重新选择来源或原文，再走完整校验。程序不自动重绑、不模糊匹配、不读取未授权或未检索的资料。

评测新增 `program_feedback`，记录下一轮模型实际收到的纠错信息。本轮后续定向测试真实触发一次：错误引用被拒，反馈指向已读简历，模型重新选择简历来源及其原文片段，计划再次校验通过。拒绝步骤和新提交均在轨迹中保留。

### 内部 ID 规则未在工具定义中公开

完整回归中，单次方案返回了带中文的内部 ID，程序按已有 ASCII 规则拒绝，但工具 schema 未声明该规则。补齐共享的 `pattern`、40 字符上限及具体错误提示；内部 ID 使用 ASCII，展示标题继续支持中文。允许的业务数据集合没有放宽。

该参数声明是在完整 18 项回归之后补齐，另行运行三场景三方案定向测试；它的结果不拼入前面的全量统计。

### 澄清暂停不能由网络错误冒充

评分器原本只核对 `PAUSED`，因此模型请求中断也可能满足“缺少信息应询问”的期望。新增失败复现后，改为必须有实际澄清问题且没有调用错误；明确标注的受控未知结果保护案例仍单独判断。用保存的 54 条对照结果重算，本轮统计未变，九条澄清响应均有实际问题，没有新增模型调用。

## 追加重复与定向验证

- 15 分钟动态场景追加三次同输入试验，三次均完成，各一次模型调用；每次均保留结果。这是同一输入的有限重复，不代表更广泛任务分布。
- 内部 ID 声明补齐后，30 分钟、15 分钟、缺少简历三个场景：动态 3/3、固定 3/3、单次 2/3 通过程序期望。单次方案的一项引用错误保留。
- 后一组 15 分钟动态任务共三次模型调用，实际发生一次“引用拒绝 → 返回简历候选 → 模型重新选择 → 再次校验通过”。该记录证明这条纠错路径可用，不意味着引用语义已经全面验证。
- v4 一致输入重点回归的失败、v5 单次目标结果、18 项完整回归、三次重复与末次定向测试分别存档，未合并成一个新的成功率。
