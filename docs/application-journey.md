# 从选岗到申请专属准备

流程：招聘来源与岗位雷达 → 公司内比较和批次名额 → 投递计划 → 官网手动投递与材料留档 → 通知关联和改期 → 按本次材料准备。

## 使用流程

1. 保存已核对的求职资料，通过已有来源导入岗位。
2. 在岗位雷达切换「公司投递决策」。自动候选最多 16 个，并显示本轮未纳入数量，不代表官网全量。
3. 根据官网在投递进展登记公司、批次、岗位范围、名额和规则链接。相对排序解释适配；后端按各批次剩余名额给出整组计划。未知规则不自动分配名额，已有申请不会重复占新名额。
4. 核对后确认整组加入计划。名额检查、计划、快照、事件、重放回执一起提交；任一项冲突，整组回滚。
5. 官网手动投递后，打开「申请档案与准备」→「核对材料并记录已投递」。可补充本次简历正文，读取完整预览后确认；资料/JD/规则变化会使旧预览失效。
6. 在「招聘通知」粘贴正文或导入 UTF-8 `.txt` / `.eml`。读取后保存待确认项，不更改申请。核对候选依据，手动选择申请、类型和活动时间。
7. 面试改期必须选择原面试与新时间；多个时间不自动判断。确认事务更新申请、面试、通知与事件；重复确认复用原结果。
8. 档案展示固定 JD、个人材料、简历正文、原分析、批次依据、确认通知和面试安排。当前资料修改不会替换留档；既有面试复盘继续可用。

导入不发送邮件、不访问正文链接或远程图片、不读取附件、不调用模型。类型和时间只是提取建议。无时区完整日期按北京时间解释；缺年份、缺时间或复杂格式人工填写。唯一时间也可能是回复截止，确认前需核对。

## 数据迁移与一致性

- `014_application_journey.sql` 增量创建 `application_contexts`、`recruitment_notices`，启动时幂等执行。旧表和历史记录保留，不回填历史正文，不提供自动 downgrade。
- 新计划保存 `PLANNED`，记录已投递保存独立 `SUBMITTED`。`(application_id,phase)` 唯一，业务只插入不覆盖。
- 快照保存 schema 版本、依赖摘要、岗位/JD/观察编号、当时可见来源的链接与信任标注、观察时间、个人正文、可选简历正文、有效单岗分析、批次规则、最近五份历史公司比较。历史报告保留原范围，不能当作当前全量比较。
- 预览摘要绑定完整内容。确认在用户锁、岗位锁下重新读取校验；批量确认按稳定岗位顺序加锁并重新核对输入和完整公司工作流。显示时钟不使决策摘要失效。
- 兼容旧 API：未传预览摘要仍保存可取得的当时材料，`reviewed=false`，界面明确标识。资料缺失保持空缺。
- 升级前已投申请没有历史快照，返回 `legacy=true`，不将今天资料当作过去提交。旧计划今后记录实际投递时可保存提交阶段快照。
- 档案按当前账号隔离。新留档不会复制不可见来源元数据。升级个人数据库前沿用 `./campustrace backup`，再 `./campustrace restart --build`；本轮没有对用户已有服务执行这些操作。

## 去重与失败恢复

- 每账号按 Message-ID 去重，没有时按解码主题、发件人和正文摘要去重；同一 Message-ID 不同内容返回冲突。不同导入形式的不同正文表示不保证合并。
- 同内容重导返回原通知。确认包含通知/申请版本，同一请求重放不重复创建面试；确认过的通知换参数会冲突。
- 申请编号完全一致、岗位名、公司名分别作为候选依据。公司名不能唯一对应岗位；没有候选仍可手动选择本人申请。候选/选择载入最近 500 条申请，列表显示最近 100 条通知，每账号最多 2,000 个导入项。
- 改期校验原面试 ID 与原时间；已完成、已改期或申请版本过期返回冲突。失败保留填写，可重新打开通知读取最新数据后再确认。
- 提交前失败全部回滚，通知保持待确认；响应丢失可原样重试或重开通知检查状态。写操作不会静默自动重试。
- 本轮未实现：真实邮箱 OAuth、附件/日历邀请、复杂自然语言时间、已确认后的重新关联、阶段回退；笔试时间用跟进提醒保存。原始通知和确认历史可回看。

## Agent 边界

普通问答保留动态工具循环，新增只读 `get_application_dossier(application_id)`。讨论某次申请时先查本人申请，再读固定档案；历史缺失保持未知。文本沿用脱敏，输出超限由现有预算阻止，不截断后假装完整。成功观察可导航到对应申请。

该工具不确认通知、不投递、不触发匹配。岗位级常用准备任务仍是固定查询流程；新增工具没有扩大外部 stdio MCP 白名单。合成流程测试不能证明真实模型准确率。

## 可重复的本地演示

需要 Go（符合 go.mod）、Docker、Python 3，以及已缓存的 Go 依赖和 `mysql:8.4`、`redis:7.4-alpine` 镜像。脚本禁用 Go 下载，不读取 `.env`、不挂载业务卷。

```sh
scripts/journey-local.sh demo
```

打开 `http://127.0.0.1:23380`，合成账号 `demo@campustrace.invalid` / `Synthetic2026!`。HTTP 仅监听 loopback，可设 `JOURNEY_HTTP_PORT`。脚本用 PID 命名临时容器，随机数据库端口、tmpfs MySQL、临时二进制，只初始化空 `campustrace_journey_demo` 库。Ctrl-C 清理本次容器与临时目录；下次重新开始，账号和数据不持久保留。

演示含三岗位、两名额、合成资料和明确标注的预置比较；不抓真实来源或调用模型。手动通知样本：`examples/journey/interview.txt`、`examples/journey/reschedule.eml`。

在**刚启动、尚未操作的新演示**上运行：

```sh
python3 scripts/smoke-journey.py
```

烟测仅接受 loopback 合成账号，令牌只在内存；会改变演示数据。覆盖整组确认重放、投递预览、资料变化快照不变、重复导入、歧义、旧版本拒绝、确认重放、EML 多时间和改期。完成后可从页面查看申请及通知历史。
