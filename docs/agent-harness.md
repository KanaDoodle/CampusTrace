# 求职助手：任务、上下文、恢复与外部资料

入口是 **更多工具 → 求职问答**。这轮增加了六项能力：任务化 Skills、上下文选择、失败反馈与恢复、MCP 资料客户端、模型分工与预算、招聘变化待办。完整核对资料、长期记忆、Go 练习和原有业务确认流程继续使用。

## 怎么用

### 常用任务

“也可以直接做这些事”提供四种任务：

| 任务 | 填什么 | 读取哪些内容 |
| --- | --- | --- |
| 同公司岗位取舍 | 公司全名，例如腾讯 | 完整核对资料、本地岗位、已有公司比较、该公司的记忆 |
| 岗位面试准备 | 岗位详情中的岗位编号 | 完整核对资料、岗位准备依据、薄弱点、真实练习记录 |
| 复盘与复习 | 主题，例如 Redis Streams | 面试复盘、薄弱点、练习记录、本地学习资料 Top5 |
| 今天的求职待办 | 无需填写 | 招聘变化、7 天内截止、最近变化、投递记录 |

它们是版本化、经过程序审核的固定查询流程，每项最多四个步骤。查询已有深度分析，不自行发起新的付费分析。结果来自实际读取的记录；没有有效公司比较时会提示补齐，不能假装已经替所有岗位排好了名次。外部模型仍可在普通问答中按问题选择工具；常用任务本身不调用模型。

任务中断后会显示“继续未完成的步骤”。点击后保留已经完成的查询，只执行剩下的部分。两次点击或网络重试使用同一请求编号：相同内容返回同一任务，修改内容但复用编号会被拒绝。服务崩溃后，运行租约过期才能接管；同时只允许一个执行器持有该任务。资料、有效记忆、相关源数据、模型身份、遮盖设置或执行版本变化后，旧检查点失效，需要发起新任务。

这与“继续这次讨论”不同：后者仅载入旧讨论摘要，再查询当前数据，不恢复付费模型请求。任务记录由当前账号持有；页面显示最近 20 条，完整资料依据按需打开。每账号每小时最多创建 30 项任务、同时最多两项执行；单任务最多启动/继续五次，耗尽后进入 FAILED，不再提供继续按钮；是否能继续由后端实际租约决定，前端不按时间戳猜测。每次执行时限 35 秒、每个工具 8 秒。每项输出不超过 32 KB、累计依据不超过 96 KB，超过时暂停，不能截一半资料当完整结果。

### 上下文与失败反馈

问答先按问题选择相关工具和最多五条有效记忆，带入最多六轮短期对话。中文问题通过词组匹配选择记忆；有公司范围但不相关的记忆不会仅因较新就进入上下文。完整求职正文需要时通过工具读取，项目和学历不会重新切成碎句。结果中可查看本次选择的记忆、工具、路由和上下文大小。

工具失败会区分参数问题、记录不存在、输入过期、超时、取消和临时网络故障。错误不包含远端原始响应或密钥。临时只读网络故障最多额外重试一次，计入工具次数；写操作预览和模型请求不自动重试。模型会看到结构化失败及下一步提示，可以在既有步数、权限和预算内调整后续工具。没有增加第二个“评审模型”，也没有无限反思循环。

### 问答预算与模型分工

展开“问答设置”：

- 简单记录查询可以使用本地确定性路由，不调用外部模型。
- 普通问题使用当前模型；比较、准备、复习等复杂问题可使用另一款已配置密钥的模型。
- 默认单次预算为 48,000，最大 200,000；每轮输出上限 2,048。每次外部请求之前先检查剩余预算和上下文容量。

请求前的准入数是基于序列化字节的保守估计，**不是账单 token**。提供商返回完整 usage 时，界面显示实际输入/输出 token；缺少 usage 时采用估计并明确标示。没有货币费用预测，也没有余额查询；实际消费以提供商账单为准。复杂模型需要明确选择，不会在服务失败后悄悄换提供商。任务历史不保存模型密钥。

### 外部学习资料（MCP 客户端）

填写资料来源名称、公共 HTTPS MCP 地址和访问令牌（需要时），点击读取可选资料，勾选允许读取的文本资源后保存。地址需要支持 **Streamable HTTP 和 resources/list、resources/read**；仅有 tools 的服务、stdio 命令、本机地址、传统 SSE 地址和需要跳转的接口不在这一版范围内。

客户端仅列资源和读取明确选择的资源，不调用远程 tools，不执行命令，也不会接受模型扩大授权范围。配置归当前账号；令牌只保存在当前浏览器的账号范围内，单次请求临时传入后端。资源地址留在本地配置中，模型使用资料编号；目录名称和读取的脱敏文本可能发送给本次问答模型。最多十个连接、每个连接五十份授权资源；目录最多五页/一百项，单份文本最多 24 KB，响应有大小、时间和公共 DNS/IP 限制。

问答可说“查看我的 MCP 资料”，随后选定来源和资料编号让助手读取。资料属于不可信学习参考，不能证明你掌握某项技术或某岗位仍可投递。本地 RAG 的 Top5 检索继续独立工作；本轮没有替换为语义 embedding，也没有引入自动网页搜索。

已有 stdio MCP **服务端**现在提供十个业务只读工具：岗位搜索、详情、原文证据、投递资格、本地知识检索、已有深度匹配、公司比较、分析进度、招聘待办、练习记录。客户端和服务端是两个不同方向的接入。

### 招聘变化待办

主动开启后，对之后的新增岗位、JD 更新和求职资料（包括项目正文与事实）变更生成站内待办。相同岗位/类型的未处理事项合并；点击“已处理”移除。关闭后暂停处理，重新开启会继续处理积累的变化。首次开启不回补旧事件。

事件和业务变更在同一 MySQL 事务里保存，后台每分钟或页面查询时按持久游标处理，每轮最多两百个事件。任务只读取本账号可见的岗位，跳过已忽略项。新增提醒仍需要按主投方向筛选，不代表系统已经确认适配或可投递；它不会自动调用模型、重新分析、提交申请或发送外部消息。

## 后端实现与边界

`agent_executions` 保存计划、步骤检查点、终态、版本、输入身份和执行租约；用户记录锁、唯一请求编号、租约令牌及条件更新防止重复领取和取消后的迟到写入。记忆遗忘会清空相关执行上下文，旧请求不能恢复被遗忘的正文。

`agent_connectors` 保存账号授权与版本，`agent_events`、`agent_feed_settings`、`agent_todos` 保存事件、消费游标和待办。这些是原有 MySQL/Redis 架构上的增量，没有新增 Kafka 或 Kubernetes。用户点击确认的业务写操作仍走原来的预览和回执流程。

这一版完成的是有边界的个人求职助手：常用任务是固定工作流，普通问答可选择工具，但最终业务回答由成功工具观察生成。它不是自由执行命令的通用 Agent，也不是多 Agent 系统。Go 沙箱仍需用户主动运行，未增加自动写代码、修复测试和提交功能。

## 验证

```sh
node --test web/*.test.cjs
go test ./internal/agent ./internal/analysis ./internal/mcpclient ./internal/transport
RADAR_RACE=1 scripts/verify-radar.sh
make eval
```

回归覆盖检查点恢复、不重复已完成读取、请求编号冲突、并发租约、取消后的迟到写入、资料变更失效、遗忘后的擦除、账号隔离、事件合并、工具权限、预算阻止后续模型调用、usage 缺失、脱敏后 JSON 有效性，以及真实 MCP SDK 的初始化/目录/文本读取协议。MCP 协议测试使用受控本地测试服务器；不代表已连接你的外部资料服务。评测使用合成数据，不产生模型费用，不能当作真实模型准确率。

## 页面与复查改进（2026-10-09）

问答与常用任务放在主区，招聘变化放在侧栏；任务记录、问答设置、记忆与讨论记录、外部学习资料按需展开。提醒默认显示四项，可继续展开。任务结果标明任务类型与输入范围；已恢复的历史错误折叠保存，不再作为当前失败展示。某个辅助列表加载失败时，其他入口仍可使用并提供单独重读。中文输入按 UTF-8 字节核对，避免字数看似合规但后端拒绝。外部资料仅展示可读文本资源，现有连接可更新或清除本机令牌。

恢复覆盖实际租约、五次尝试上限和其他账号不得恢复；重试仅限临时或超时网络故障，永久 DNS 错误不自动重试。新增 agent-harness.md 与 agent-workspace.md 已加入源码仓库文档白名单。
