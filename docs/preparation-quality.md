# 申请准备：依据、练习规模与补查选择

申请准备计划现在说明每条引用用于支持什么，并以可检查的练习类型、数量和产物范围安排时间。用户可以让模型按资料缺口补查，也可以选择只使用已核对材料。

## 引用与练习规模

新计划采用 `application-preparation-agent-v7 / preparation-quality-v2`。引用增加 `supports`，说明原文中的具体要求、机制或限制如何支持行动；提示明确排除口号、标题和不相关引文。界面展开依据即可查看“用于说明”，保留原逐字引文与来源。

每项 `workload` 包含 `mode / units / scope`。scope 以数量开头，例如 `1个问题：TCP半包如何处理`；显式数量必须与 units 相同。新计划的准入门槛如下：

| 类型 | 一个单元的产物 | 最少分钟 |
| --- | --- | --- |
| ORAL | 一个具体问题的复述与自查 | 5 |
| READ | 一个明确材料片段及核对笔记 | 10 |
| MODIFY | 一个已有示例的修改与验证 | 15 |
| CODE | 一道小题或小型示例及基本测试 | 30 |

因此，35分钟声明完成3个CODE单元会被拒绝：至少需要90分钟。应减少题目、缩小产物，或者拆成一次编码与一次简短核对。算法技巧和设计模式分别准备，不把二者混称。

15分钟及以下最多两项，每项一个ORAL或READ单元。校验反馈一次列出所有条目的分钟、数量、scope数量和可容纳上限，要求同时修正，避免每轮只修一个冲突。

这些是保守的产品准入规则，不是个人学习速度测量。supports是模型的关联说明，不是系统已经完成语义证明；自然语言也可能把多个关联主题藏进一个“问题”，仍需审阅。旧计划没有这些字段时继续按原规则读取、校验和恢复，不伪造新字段。

## 何时补查

新检索调用先说明 `gap / expected_use`：已有材料缺少什么，以及补到后将支持哪条准备行动。Go仅把经过校验的query传给原有本人范围工具，账号与授权范围不由模型指定。

- 一般任务最多3次补查；15分钟及以下最多1次。依据足够时可以零读取直接生成。
- 连续两次失败、空结果或没有新来源后停止扩大查询，使用现有依据或询问。
- “只用本轮已核对的材料”对应 `retrieval_mode=off`：模型没有检索工具，受控接口也拒绝绕过调用。已有上一版读取材料仍属于核对范围，不冒充新的检索。
- SQL执行记录保留缺口、预期用途、新来源及最终引用情况，并绑定Go持久步骤游标。节点恢复不会因提供商重复call ID合并两次独立读取。

诊断区展示新增与被引用的来源数。这些表示材料采用情况，不能代替检索质量或因果增益。自动/关闭补查的对照使用同一模型、材料范围、时间与调用预算；自动模式若也没有检索，就没有形成“有检索与无检索”的质量比较。

## 本机后端模型配置

经用户明确授权，本机配置保存在 `.env.model.local`，权限0600。该文件由`.gitignore`和镜像构建忽略规则排除，包含 `LLM_URL / LLM_MODEL / LLM_API_KEY`，密钥不写入文档、日志、检查点或命令参数。

正常 `make run` / `bin/campustrace`、Makefile应用Compose命令和 `make dev-run` 均读取专用配置；一般`.env`先加载，专用模型文件随后覆盖对应设置。Python服务不接收模型密钥，模型请求继续由Go发出。

评测可直接从同一文件导出环境，不再读取浏览器：

```sh
set -a
. ./.env.model.local
set +a
# 仍须明确授权任务文件哈希及请求次数，并按LangGraph运行文档启动评测服务。
GOWORK=off go run ./cmd/preparation-eval -live -arms dynamic \
  -dataset '<authorized-private-task-file>' -only '<case-id>' -split validation \
  -url "$LLM_URL" -model "$LLM_MODEL" -key-env LLM_API_KEY \
  -authorize-material-sha256 '<exact-file-hash>' -max-calls '<authorized-limit>' \
  -graph-url http://127.0.0.1:18120 -graph-callback-addr 127.0.0.1:18112 \
  -output /tmp/private-preparation-result.json
```

当前图模式的单例dynamic评测支持更低的1—5次硬上限；Go在下一次派发前检查额度，耗尽结束为已知预算失败，不将未发送的请求记作UNKNOWN。多例/多组仍要求覆盖所选最坏预算。配置文件的存在不构成新增真实评测授权。

本轮调用沿用原120次账本，已用满后停止，没有自动扩大额度。阶段化结果、原始失败和剩余边界见[本轮验收](verification/preparation-quality-20261101/README.md)。

## 目标使用者审阅与实际执行

使用 `scripts/build-preparation-human-review.py` 将已有单例报告及其原始任务整理成离线审阅包，不调用模型。选择文件为 JSON 数组，每项包含 `label`、`report`、`dataset` 三个字段；路径指向仓库外的既有报告与任务集。可在一个已完成的15分钟任务上设置 `exercise: true`，同时生成实际执行记录表。

```sh
python3 scripts/build-preparation-human-review.py \
  --selection '<private-selection.json>' --output '<new-private-directory>'
```

导出前检查报告绑定的任务集哈希；输出目录必须在仓库外且尚不存在，避免覆盖人工评价。审阅页包含实际计划、约束、反馈前计划、引用来源原文及执行轨迹；每例的 `scores.json` 复用现有评测审阅格式，初始分数均为空，原报告逐字保留并以哈希绑定。

目标使用者填写六个维度的分数与具体证据，身份标为 `TARGET_USER_SELF_REVIEW`，不视为独立专家标注。先填写，再阅读既有助手审阅，可减少直接照抄判断。语义评分和程序准入结果分别记录，跨版本结果不合并成成功率。失败、无收益检索也保留在审阅范围。

实际执行时按原计划计时，到15分钟停止并记录已完成产物、卡点、剩余工作和额外时间；提前掌握情况与中断单独说明。一份完成记录用于校准本人可执行性，不推广为通用学习速度或用户收益。选择任务属于定向回顾，不能称为未参与调试的保留验证集。

后续真实保留验证在新增额度明确授权后进行：冻结少量新任务、材料及版本，检索对照固定其他条件，按实际是否检索与获得有效信息解释结果。当前审阅包不会触发新的请求。
