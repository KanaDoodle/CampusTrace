# 学习资料检索

把复习笔记放到 **更多工具 → 学习资料**。默认只在本地用关键词搜索；有时知道大意、记不住术语，就可以开启语义检索。

## 怎么用

1. 添加材料标题和正文，也可选择 `.txt` / `.md` 文件。正文最多 60,000 字节，标题最多 200 字节；中文通常每字占三个字节。保存材料不会外发。
2. 在 **模型设置 → 学习资料检索** 填写检索服务密钥。内置硅基流动的 `BAAI/bge-m3` 和 `BAAI/bge-reranker-v2-m3` 预设，接口及模型可自定义。聊天服务的密钥和模型不会自动用于检索；例如 DeepSeek 聊天配置不等于 Embedding 配置。模型可用性、额度与账单以提供商为准。
3. 回到学习资料，点击 **预览下一批外发文字**，核对脱敏正文、模型和目标接口。确认后，每批最多建立 32 段索引；已完成片段会跳过，剩余片段可继续预览下一批。
4. 勾选启用语义检索后，用自己的话提问。页面显示出处、片段和检索方式。求职问答、复盘与复习、岗位面试准备也会使用本次账号的检索配置。
5. 先观察结果，再决定是否开启重排序。它只排列最多 20 个候选片段，不扫描或外发整库。

搜索片段上的「阅读完整材料」、材料列表的「查看」，以及求职助手给出的阅读入口，都会打开本地保存的完整正文，方便核对上下文。这些阅读不会调用检索模型；每次都重新核对当前账号的访问权限。删除材料后，旧入口会提示无法读取，正在读取的旧响应也不能覆盖新打开的材料。

密钥按账号留在此浏览器的本地存储，保存设置不会调用服务。请求期间密钥临时经过本地后端并传给所选服务商，不存入 MySQL、索引、日志或 Agent 检查点。语义索引发送核对过的材料；搜索发送脱敏问题；重排序另发送候选材料。自动遮盖沿用姓名遮盖设置与手机号、邮箱等规则，仍应核对实际预览。检索调用独立于聊天调用，问答 token 预算不充当检索账单预算。

模型未配置、索引不完整或服务失败时会显示原因并使用可用的关键词结果；不会后台重新向量化整库、换提供商或自动重试付费请求。关闭语义检索不删除材料。清除语义索引会保留本地材料；删除某份材料会同时删除对应向量。材料正文目前通过删除后重新导入来更新，未做文档版本编辑或同内容导入去重。

## 检索流程

材料仍保存在 MySQL，切成 900 个 Unicode 字符、步进 700 的重叠片段。默认 BM25 处理当前账号的全部可用片段，保留技术术语的字面命中；中文采用 bigram 分词。旧 128 维 lexical-hash 字段仅供兼容，不再参与新关键词排名，也不能称为语义向量。

启用语义检索后，对已建立索引的片段计算真实模型向量的余弦相似度。两路各最多取前 40，按 RRF（k=60）合并，保留 20 个候选；重排序启用时对这些候选再排序，页面和 Agent 默认取前五。当前语义候选最低余弦值为 0.25，它是可复查的初始阈值，不代表跨模型统一的相关性概率，需要用实际材料标注校准。

`knowledge_vectors` 按账号、片段、模型空间保存向量；模型空间包含接口、模型标识与脱敏输入协议版本，片段另绑定脱敏输入哈希。密钥不进入身份。切换模型、正文或姓名遮盖规则后，旧空间不能冒充当前索引。响应必须逐项对应输入，维度一致、数值有限且非零；同一模型维度变化时要求清除重建。问题向量缓存五分钟、最多 256 项，账号、模型和知识库版本隔离，不保存原文问题或密钥。

容量为每账号 10,000 个片段，向量缓存最多 20,000 行；增加模型空间可能需要先清除旧索引。单批输入正文最多 100 KB，模型响应最多 4 MiB，向量最多 4,096 维。外部请求最多六秒，并为输入复查预留时间，遵循工具总体截止时间；共享并发槽与限流限制调用。仍在个人资料规模上进行 MySQL 扫描和内存余弦计算，没有引入 ANN 或独立向量数据库。

索引使用账号级 30 秒租约防止两个页面重复支付同批请求，外部请求在事务外完成。保存时在用户锁下再次验证输入与租约，一批原子提交。删除材料、清除索引或失效租约之后，迟到响应不能恢复旧向量。Agent 的检查点与历史摘要绑定知识库版本及检索设置变化，避免继续引用被删除的材料。

检索资料只作为学习参考。完整求职资料、JD 与同公司比较继续沿用整体分析；相似度不是岗位匹配度，也不证明某项技能已经实现。

## 检查效果

```sh
make retrieval-eval
go run ./cmd/retrieval-eval -dataset /absolute/path/to/retrieval-labels.json -output bin/retrieval-report.json
```

默认读取仓库中六个合成样例，不读取账号资料、不联网，结果只验证流程。真实评测需要自己准备脱敏材料与人工标签：`kind` 为 `human-labeled`，每个问题填写相关材料的 ID 及 1—3 的相关程度，人工核对后设置 `reviewed: true`；未核对问题不计算质量指标。数据格式参考 `internal/rag/testdata/retrieval.json`。

由助手阅读原文、辅助标注的数据应使用 `kind: "assistant-reviewed"`，核对完成的题目仍可设置 `reviewed: true` 并计算基线，但报告会保留标注来源。这样的结果适合检查检索和开展小规模对照，不能表述为独立人工金标准或真实模型回答准确率；人工抽查也不应直接把整套标签改称独立人工标注。

报告含 Recall@20、nDCG@5、MRR、P50/P95 查询耗时、失败数、回退数和调用次数。质量分母保留失败查询；没有人工标签时不产生质量分数。耗时为实际测量，不含建立索引的时间；数据规模很小时可能显示 0 ms。合成语义向量测试不是模型准确率或模型选型证据。

真实模型对照须显式开启，使用自己的已核对数据及密钥环境变量：

```sh
go run ./cmd/retrieval-eval -dataset /absolute/path/to/retrieval-labels.json -live \
  -embedding-url https://api.siliconflow.cn/v1/embeddings -embedding-model BAAI/bge-m3 \
  -key-env RETRIEVAL_API_KEY -max-calls 30 -output bin/retrieval-live-report.json
```

可另指定 `-rerank-url`、`-rerank-model`、`-rerank-key-env`。每次先跑本地关键词基线，再跑混合检索；启用重排序时在同一候选集上单独对照，复用已召回的片段；调用上限不足会在首个外部请求前拒绝，不自动重试。命令只读取明确指定的数据文件，临时向量保留在内存。它不会使用浏览器已有密钥，不会读取数据库。默认最多 12 次、可显式增至 192 次；数据最多 64 份材料、256 个片段、64 个问题、文件 1 MiB。材料采用与实际索引相同的分段方式；相关性标注使用材料 ID。

接口协议参考：[硅基流动接口与密钥](https://docs.siliconflow.cn/docs/userguide/quickstart)、[重排序文档](https://docs.siliconflow.cn/docs/api/rerank-post)。两阶段检索参考 [Sentence Transformers](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)。


## 批量导入与继续阅读

「学习资料 → 批量导入 TXT / MD」支持一次选择最多 64 份、共 1 MB 的文本文件，每份正文最多 60,000 字节，文件名作为标题。浏览器先展示预览，点击「导入勾选材料」才逐份保存，不会调用外部模型。同账号、标题与正文完全相同的已有材料自动跳过；改名或修改正文视为另一份材料。

保存接口与资料删除共用用户行锁，在事务内检查重复、写入材料和片段并更新资料版本。并发提交与响应丢失后的重试不会重复创建相同材料。成功项保留结果，失败项可单独重试；停止或离开页面只停止后续请求，正在处理的一份仍可能完成。本批暂存在页面内存，登录退出或刷新后不保留文件正文。

本次登录期间，页面会记住问题、结果、材料分页和阅读位置。返回时先检查资料版本与检索设置；变化后提示重新搜索，不展示旧结果，也不自动重新调用模型。材料全文重新读取本地记录。搜索结果和批量文件正文不写入浏览器持久存储。
