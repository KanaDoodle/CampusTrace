# 申请专属面试准备 Agent

把“我只有三小时，三天后要面试这次申请”转成可检查的准备计划：每项标明依据类型、安排时长、行动和完成标准。用户可以补充信息、标记掌握/完成情况，再核对下一版输入并调整剩余计划。

默认主链路现由 Python / LangGraph 编排，Go 保留业务工具、模型预算与确认提交。[部署、检查点、恢复与迁移说明](preparation-langgraph.md)。

## 使用与演示

第一次接触项目，可先阅读 [15分钟流程入门](preparation-first-run.md)，认识申请材料、计划、反馈与确认保存。该阅读任务无需模型调用。

“准备方式”中的[练习讲清项目](project-defense.md)可围绕当前项目证据提交回答、阅读后复述，并把待复习事项确认保存。模拟练习与真实面试复盘分别记录。

1. 在投递进展打开一条申请的档案，点击 **准备这场面试**。也可从求职问答打开同一页面。核对本次申请，选择安排准备计划或练习讲清项目，再填写目标、总分钟数和天数。
2. 使用模型设置中已配置的问答模型，或服务器 `LLM_URL / LLM_API_KEY / LLM_MODEL`。点击 **核对材料与调用范围**，查看实际冻结材料、缺失项、模型及时间预算。此步骤不调用模型。
3. 勾选确认后开始。页面显示模型与检索次数、缺失信息、计划及执行过程。模型可以选择本地知识检索、检索授权的本人其他申请复盘、有限改写查询、提出一个澄清问题，或提交结构化计划。
4. 在结果中把一项标为 **已经掌握** 或 **本项已完成**，将剩余时间改为 60 分钟，也可以补充“只剩一小时”。重新核对输入后生成新版。修改保留原项目 ID 和标题，可重排、删减或重新分配时长；掌握/完成项不再安排。需要新增不同主题时，从主表单创建新任务。
5. 点击 **核对并保存计划**，再点击 **确认保存这版计划**。计划保存到当前申请的任务记录，刷新后可从“这次申请的计划记录”读取；不会修改投递阶段、复盘或项目事实。
6. 取消后任务保留取消终态。执行中断可继续未完成步骤；如果模型结果未知，需要明确确认可能已经处理或计费，再授权新尝试。缺失信息用补充输入建立下一版，并通过 LangGraph `Command` 关联上版澄清中断。

最直接的本地演示与浏览器检查：

```sh
python3 scripts/verify-preparation-agent.py \
  --output /tmp/ct-preparation-demo-new \
  --playwright-module /absolute/path/node_modules/playwright
```

该脚本启动自己的 API、MySQL、Redis、Kafka 和脚本化 HTTP 响应，不读取 `.env`、个人账号或现有数据库。截图和 JSON 证据保存在指定的新空目录；退出清理本轮进程和容器。它演示程序行为，不运行真实模型。

## 数据与引用

- 本次 JD、简历和项目材料来自 `application_contexts`，优先采用实际投递留档。计划阶段留档单独标明；历史申请缺少快照时，不读取今日 JD 或个人资料补作当时材料。
- 初始上下文包含本申请的已保存复盘和已确认通知。用户可选择允许模型检索本人其他申请最近 50 条复盘；检索结果保留原申请编号，不混称为本次面试经历。
- 学习检索复用现有 RAG 的 BM25，返回本账号的相关片段。本场景不隐式调用 Embedding、重排序、MCP 或深度分析模型。知识材料用于复习，不建立个人已掌握能力。
- 来源分为 `JD / RESUME / PROJECT / HISTORY / KNOWLEDGE / NOTICE`，具有记录编号、文本哈希和稳定引用编号。每条计划区分“岗位要求”“历史失分与复盘”“一般建议”。前两类必须引用对应类型来源，引用文字必须是已读取材料中的逐字片段。
- 引用校验确认编号、类型和文字绑定；语义上是否支持整条建议仍需人工检查，真实任务评测单独记录。材料缺失集中显示，不靠模型自行决定是否提示。

## 执行设计

模型负责有价值的后续选择和计划综合，程序控制范围与提交。初始化读取冻结材料属于程序上下文准备；后续工具路径不由固定计划表决定。

`PreparationRunner` 复用现有 `Model / LiveModel`、工具定义、错误分类、Token 准入估计、Store、RAG 和确认回执，通过内部受控接口向 LangGraph 提供一次模型或工具操作。LangGraph 状态图接收模型选择并通过条件边组织检索、澄清和结束；每一步将观察反馈给下一轮，结构化计划通过 Go 的时间、来源和剩余事项校验后形成结果。

工具参数定义随任务约束收紧：天数和单项分钟数使用实际预算；调整计划时仅提供剩余项目的 ID、标题与依据类型候选。程序继续校验字段配对、总时间和引用；拒绝时返回具体条目及校验原因，供模型修正。

生成提示采用紧凑计划，数量按 `min(4, 总分钟/5, 剩余事项数)` 收紧，行动、产物和逐字引用分别限制长度，以适应 2048 输出 Token 上限；旧计划仍按原有读取与校验边界兼容。所有方案通过同一消息构造器接收已核对的总分钟与天数，旧目标文字不能覆盖本轮数值约束。界面目标不再预填固定时长，总准备时间明确为所有日期合计。

连续检索仅把新来源正文加入模型上下文，已读来源返回编号，完整读取观察继续保留。已返回但 JSON 无效的工具参数不会执行；在工具及模型预算允许时，保存可序列化反馈，给模型一次新输入的格式修正机会。再次错误则停止。这与未知模型请求不同：网络中断或未保存响应仍需用户核对后授权新尝试。

引用校验失败时，程序只在已读来源中查找包含该原文的候选，保留来源类型与申请范围，要求模型明确重新选择后再次校验；不会自动重绑或接受近似引文。工具定义与校验器共享内部 ID 字符规则，中文展示标题继续保留。

业务执行上下文继续保存在 `agent_executions.body.preparation_agent`；新增 Python 服务使用持久 SQLite Checkpointer 保存图游标、单步回执序号和中断关联，不保存材料正文或模型凭据。一次执行沿用用户锁、请求编号、租约令牌、60 秒领取租约、最多五次启动/恢复、每账号最多两个运行任务及每小时最多 30 次创建限制；进程内最多四项活动执行，模型 HTTP 共用原有并发额度和限流。新增任务启动/恢复另有每账号每分钟五次限制。

默认每轮最多六次模型调用、八个工具步骤、三次检索（含改写），最长 35 秒、单次读取最多八秒。模型上下文上限 96 KB，单份工具结果 32 KB，累计来源 128 KB，初始材料 96 KB；不接受截断的来源作为完整依据。每次模型请求按序列化体量估计准入，发送前将预算预留与 `DISPATCHED` 一起保存；有 usage 后结算，未报告或进程强杀的请求保留估计占用。这个预算不是货币余额。

### 检查点与恢复

- 模型调用前持久化派发意图，响应和所选后续工具持久化后才执行读取。进程强杀后，未保存响应的派发保持未知，不自动重试。
- `plan` 存动态追加的工具动作，`next_step` 只前进到已记录结果的位置。已经完成的读取不重放；在读取期间崩溃时，仅重新执行未完成的只读步骤。工具失败反馈给模型，后续可改写或结束；不会把失败观察当作证据。
- 申请留档、相关复盘、通知、知识库版本和记忆版本共同绑定输入身份；当前个人资料/JD不替换历史快照。恢复前和检查点时重新核对，发生变化后需新建任务。
- 取消先保存 SQL 终态并撤销租约，再取消活动 Context；迟到结果不能覆盖取消。遗忘记忆同时清空本场景的消息、来源和计划上下文。
- 计划保存通过已有 Redis 待确认动作和 MySQL `action_receipts`。确认事务在用户锁下再次校验账号、申请版本、计划版本/哈希及来源身份；重复确认返回相同回执，资料变更后拒绝旧提案。

## 评测与证据

[24 个可审阅任务](../internal/agent/testdata/preparation-tasks.json) 全部为合成控制，6 个调试案例、18 个保留验证案例。覆盖时间约束、缺少简历/项目/复盘、历史快照缺失、无命中、查询改写、检索失败、掌握/完成反馈、时间缩短、注入文本、来源变更和跨账号边界。每例记录材料类型、预期和审阅说明。

```sh
GOWORK=off go test -race ./internal/agent -run TestPreparation
python3 scripts/evaluate-preparation-langgraph.py --output /tmp/prep-langgraph-evaluation-new
python3 scripts/verify-integration-isolation.py --race --count 1 --adversarial
node --test web/*.test.cjs
```

三种对照使用同一模型接口、材料授权范围、目标与预算：

1. `single-prompt`：一次生成，小规模语料全部放入允许范围，作为较强的直接提示基线。
2. `fixed-plus-synthesis`：复用旧申请准备的字面检索查询与 BM25，固定一次检索后做一次综合。为了共用约束检查，对旧模型说明增加结构化计划适配，不能把它当成原有页面已支持时间规划。
3. `dynamic`：模型从初始冻结材料出发，选择检索/改写/澄清/提交计划，使用实际 LangGraph 状态图；历史 Go 循环仅作显式对照。

报告保留终态、约束检查、引用来源、依赖失败与无效调用、重复查询、耗时、调用次数、usage 和可选单价估算，并记录模型返回的工具参数、被拒绝候选和失败原因。报告包含所授权任务的文本，分享前需审阅材料范围。允许不同有效检索路径，不要求固定工具顺序。CLI 三组都是只读评测；真实业务写入由独立 SQL/API/浏览器验收检查最终保存状态和回执，不用回答文本代替写入验证。

真实模型评测不会读取浏览器密钥或隐式使用服务器环境配置。需要明确指定模型地址、名称、密钥环境变量，并授权数据文件 SHA-256；配置不全则在首次请求之前拒绝：

```sh
# 先按 preparation-langgraph.md 启动独立评测服务与回调地址，再核对授权额度。
shasum -a 256 internal/agent/testdata/preparation-tasks.json
GOWORK=off go run ./cmd/preparation-eval -live -split validation \
  -url 'https://your-authorized-provider.example/v1/chat/completions' \
  -model 'your-authorized-model' -key-env AUTHORIZED_PREP_EVAL_KEY \
  -authorize-material-sha256 '<exact-dataset-sha256>' \
  -graph-url http://127.0.0.1:18120 -graph-callback-addr 127.0.0.1:18112 \
  -max-calls "$AUTHORIZED_PREP_MAX_CALLS" -output /tmp/prep-real-model.json
```

可用 `-only` 或 `-limit` 缩小范围；默认三组的请求上限需覆盖每例最坏八次调用，避免只跑前面的组。也可显式 `-arms dynamic` 做最多六次调用的单方案专项，或选择 `single-prompt` / `fixed-plus-synthesis`，专项与完整对照分开报告。文件最多 1 MiB、20—30 个任务，真实脱敏材料需标为 `human-approved-desensitized` 并重新明确授权。费用只有提供商返回 usage 且用户提供单价时才估算，其他情况为 null；失败和无收益结果保留。模型语义效果由单独人工审阅判断，不能以程序通过率代替。

## 使用边界

当前实现聚焦一条申请的时间规划与反馈，不修改简历、不自动投递或记忆掌握状态。计划调整从上一版剩余事项中选择；跨主题扩展重新建任务。任务历史按申请读取最近 20 项。新 JSON 状态由升级后的 API 处理，部署时同步更新 API，避免旧 API 接管新类型。

程序与界面验收见[受控验收记录](verification/preparation-agent-20261101/README.md)。随后沿用用户授权的网页 DeepSeek Flash 配置，对三个调试案例运行真实模型，并复测一小时调整场景，共 17 次请求。动态方案完成三小时准备，并在缺少快照时询问；初次调整计划失败，补充约束定义与具体反馈后，单次复测生成了 60 分钟剩余计划。单次生成也能通过程序校验，却仍把已掌握内容安排进剩余项目，说明语义审阅与程序校验需要分别记录。[真实模型报告与失败原文](verification/preparation-agent-live-20261101/README.md)保留全部初始结果。

随后在用户授权的现有简历、归档真实 JD 和项目材料上准备了 21 个衍生任务，实际模型调用 120 次，详见[真实材料评测](verification/preparation-agent-real-materials-20261101/README.md)。用户确认没有真实面试复盘，手册仅作为学习材料。v2 的 18 项保留任务中，动态方案满足程序期望 12 项，单次提示 10 项、固定检索加综合 9 项；后续修复回归另列，没有补入保留成绩。三小时计划、一小时约束、版本差异等场景有真实可用结果；短时规划、语义引用与实际工作量仍需独立审阅。完整个人材料和模型输出位于仓库外，Git 中只保留脱敏统计。当时 v4 的 15 分钟约束只完成单次真实检查与确定性动态回归，尚未完整真实动态复测。

后续已完成[一致输入回归](verification/preparation-agent-followup-20261101/README.md)：v5 动态方案 18/18 满足程序期望，包括短时、资料缺失和反馈；单次提示 14/18、固定检索加综合 16/18。15 分钟场景另重复三次通过，并在末次定向测试中观察到一次真实引用纠错。该轮新增 101 次请求，原结果和失败保留；任务已参与调试，不是新盲测或人工语义质量分数。评分器同时区分有效澄清与网络/预算暂停，重算已保存结果没有改变成绩。


## 引用支持、练习规模与补查选择

新计划包含引用支持点和结构化练习规模；短任务最多两项、最多补查一次，用户可选择只用已核对材料。旧计划按原规则兼容。正常启动及评测可共用本机私有模型文件。[规则与配置](preparation-quality.md)、[阶段化测试与真实失败记录](verification/preparation-quality-20261101/README.md)。
