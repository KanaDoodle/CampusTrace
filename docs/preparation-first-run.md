# 第一次认识 CampusTrace：15 分钟理解面试准备流程

这次先理解产品怎样帮助一次求职申请。前10分钟阅读下面的流程和界面示例，后5分钟用自己的话复述；无需启动服务、填写技术评分或调用模型。

## 先认识三个对象

- 申请档案：一次申请对应的岗位要求、简历和项目材料。创建投递计划或记录实际投递时分别留档，页面会标明材料属于哪个阶段。
- 准备计划：围绕这次申请，在给定时间内安排优先事项。每项有行动、分钟数、完成标准，以及可展开查看的依据。
- 保存记录：用户确认采用的某一版计划，保存在这次申请下，可以刷新后查看。

例如，岗位要求 Go 并发，你的简历包含 Go 项目。准备助手可以安排一个具体问题的阅读或口述，说明为什么优先准备它；不能仅凭简历提到 Go，就认定你已能解释全部实现细节。

## 前10分钟：沿着一条申请看五步

### 1. 选申请，核对当时材料

界面路径：投递进展 → 打开一条申请的档案 → 生成面试准备计划。

在这里填写准备目标、总分钟数和几天内完成。比如三天内总共180分钟，是三天加起来的时间。

点击“核对材料与调用范围”，展开“查看实际已读取材料”，核对是不是这次申请的 JD、简历和项目资料，同时看缺失项。这一步读取资料，不调用模型。

“冻结材料”就是留档时固定下来的版本。今天更新了个人简历，不会自动把旧申请中的材料替换成今天这份。历史申请没有留档时，页面会明确提示缺失。

你现在只需要理解：先知道助手实际看到了什么，再判断建议是否有依据。

### 2. 开始准备，得到计划

勾选核对确认后点击“开始准备”，才进入模型执行。它可以利用已读材料直接生成，也可以补查学习资料或询问关键缺失信息。

看结果时先看三个字段：准备什么、具体做什么、做到什么算完成。展开“依据”可以看到原文和它用于说明的内容。

[查看现有界面截图](verification/preparation-quality-20261101/product.png)。这是已完成产品验收的合成材料与受控模型响应截图，用于认识界面；不是本轮新生成的个人准备计划，也不是你的掌握记录。

不必评价截图中并发或索引的技术正确性。先找到计划、完成标准和依据所在的位置即可。

### 3. 告诉它你的实际基础

在“调整剩余计划”中，可以补充信息，改变剩余分钟数，并把对应事项标为“已经掌握，不再安排”或“本项已完成”。点击“核对下一版输入”，核对后再生成新版。

例如：“我还不熟悉这个项目，请先给明确的阅读入口和阅读产物，先不要让我直接解释内部原理。”

这句话表达的是学习基础，不是“已经掌握”。不熟悉的内容不要为了跳过任务标成已掌握。

计划调整保留上一版剩余事项的主题；若要从原来的并发面试准备改为产品流程入门，应在上方目标表单建立一个新任务。新目标的时间在表单中重新核对。

### 4. 确认采用，再保存

先点击“核对并保存计划”，再点击“确认保存这版计划”。结果中的“计划已生成”和“已保存”代表不同阶段。

保存后可从“这次申请的计划记录”查看。这个操作保存准备计划，不代表已经完成练习，也不代表已经投递或完成面试。

### 5. 看懂分工

```text
页面：选择申请、看材料、补充反馈、确认采用
  ↓
Go 后端：核对账号与材料、提供工具、限制调用、校验并保存
  ↕
Python / LangGraph：组织模型与工具的执行、等待补充、衔接反馈与恢复
```

把它理解为：页面接收你的选择，Go管理业务资料与提交，LangGraph组织准备过程。暂时不用解释锁、租约、RPC或检查点的实现。

## 后5分钟：写三句话

合上本文，尝试回答：

1. 准备助手主要根据哪次申请的什么材料工作？
2. 如果我不熟悉某个主题或时间变少，应该在哪里反馈？
3. 生成计划和确认保存分别意味着什么？

能用自己的话解释这三点，就是本轮完成标准。想不起来的地方记为“入口不清楚”或“概念没理解”，再回看对应一节。不要把记不住技术术语当作失败。

可直接把下面的记录发给协作者，无需填写JSON：

```text
实际阅读与复述用了多久：
第一句话（材料）：
第二句话（反馈）：
第三句话（保存）：
最不清楚的一个地方：
我希望下一步实际操作的环节：
```

这次记录反映目标使用者对流程的理解；不计作真实模型任务成绩、独立技术审阅或实际业务保存验收。指南依据现有源码与验收记录整理，尚未记录你的执行结果。

## 之后实际操作时

已配置的环境可按上述入口操作；启动与排障见 [README](../README.md#快速启动)。本轮先阅读已保存的界面和记录。现有真实评测调用额度已用满，新一轮真实生成需要另行明确授权额度。

未来做“不熟悉项目”场景验证时，可使用以下目标，同时把总时间设为15分钟、天数设为1。提供的项目材料需要包含真实的阅读入口；材料没有的文件位置和操作路径不能要求模型自行补造。

> 我还不熟悉这个项目，只有15分钟。请结合已提供的项目材料和这次申请的岗位要求，先安排一个明确片段的阅读，再让我用自己的话复述一个要点。给出阅读入口和简单的完成标准，不默认我已经掌握项目实现；缺少入口资料时指出需要补充什么。

这份目标尚未进行新的真实模型验证。现有机制会将目标送入模型上下文，并对时间、来源与保存执行程序校验；是否能真正按用户基础生成合适计划，仍需要对应任务结果验证。
