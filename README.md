# CampusTrace

**你的校招小雷达：盯更新、挑岗位、记进度 (ง •̀_•́)ง**

**中文** | [English](README_EN.md)

开了一堆招聘网页，记不住哪家更新了岗位；同一家公司有十几个开发岗，却只让投一个；投完之后，又开始翻聊天记录找面试时间……

CampusTrace 就是为这些小麻烦做的。它是一个用 **Go** 写的个人求职工具，把招聘更新、简历资料、岗位匹配、投递和面试记录放在一起，帮你少翻几个网页、少漏几件事。

```text
关注招聘来源 → 本地筛选 → 挑选岗位深入分析 → 安排投递 → 面试与复盘
```

## 它能帮你做什么

| 你遇到的事 | CampusTrace 的做法 |
| --- | --- |
| 招聘网站太多，天天刷新很累 | 关注已适配的公司来源，后台定期检查新增岗位和变化 |
| 岗位堆成山，很多一看就不是我要投的 | 按主投方向、公司、城市筛选；明显无关的可以批量忽略，之后还能恢复 |
| 每次都得重新解释自己的学历和项目 | 在「求职资料」里统一维护，也可以从简历提取草稿 |
| 不知道项目和岗位要求对不对得上 | 先做不调用模型的本地初筛，再按需让模型阅读完整材料，附上关键原文和项目依据 |
| 同公司只能投一个，选岗纠结 | 在公司投递决策里一起看首选、备选、截止时间和剩余名额，再确认要投哪份 |
| 投过什么、用哪版简历、面试到哪轮了 | 记录投递阶段、简历版本、面试安排和复盘；「今日待办」提醒下一步 |

深度分析保留完整项目与 JD，给出整体适配、关键优势、差距和待确认事项。同公司岗位另做相对排序，不再按技术名词或满足条数打分。**简历里没写，不等于你不会；热爱技术、团队协作等泛化要求不影响排序。**

对排序有不同看法？可以标注自己的首选，检查脱敏文字后导出案例，回放已有结果或自行评测模型。具体用法在[匹配评测说明](docs/matching-evaluation.md)里；合成测试通过可不等于模型会选对哦 ( •̀ ω •́ )✧。

## 先跑起来 ヾ(≧▽≦*)o

准备好 **Go 1.25.9+、Git，以及正在运行的 Docker（含 Compose）**。首次构建需要联网下载依赖和镜像。

```sh
git clone https://github.com/KanaDoodle/CampusTrace.git
cd CampusTrace
./campustrace start --open
```

等启动完成，打开 [http://127.0.0.1:8080](http://127.0.0.1:8080/)，注册自己的账号就可以开始用了。

一个入口会启动应用、MySQL、Redis、etcd 和两个 Analysis 实例，等待它们准备好。关掉终端后，服务仍然运行。平时可以用这些命令：

```sh
./campustrace status                # 看看服务有没有正常运行
./campustrace open                  # 打开网页
./campustrace logs api --tail 100    # 遇到问题时看看日志
./campustrace doctor                # 检查 Docker 和项目配置
./campustrace stop                  # 停应用，保留依赖和数据
./campustrace stop --all            # 依赖也停掉，数据卷仍然保留
./campustrace start                 # 下次继续用
./campustrace restart --build       # 源码更新后：先备份和构建，再重启
./campustrace backup                # 备份到本机 bin/backups/
```

CLI 使用固定的 `campustrace` Compose 项目名。备份和数据都留在本机；恢复方法见 [备份与恢复](docs/recovery.md)。本地配置放在不提交到 Git 的 `.env` 中，可以设置网页端口 `CAMPUS_HTTP_PORT`、`JWT_SECRET` 和服务器默认模型。部署到其他环境时，请设置独立的、至少 32 字节的 `JWT_SECRET`；默认配置用于本机使用。

## 第一次用，按这个顺序就好

### 1. 先告诉它，你想找什么

打开「**求职资料**」，填写学历、毕业届别、主投职能、城市偏好、语言和技术，再整理项目经历。

「技能与项目」里还有基础能力自评，可以补上简历没展开写的数据结构、算法、操作系统、网络、数据库基础和计算机系统结构。按实际情况选了解、熟悉或有实践；留空只是没填。自评能支持匹配，但不会自动变成项目经历。

也可以点击「导入简历」，选择文字版 PDF、DOCX 或 TXT。文件先在浏览器本地读取，你检查并修改脱敏预览后，再确认交给模型整理。返回的条目**默认全部勾选**，可以改写或取消；点击保存后才进入求职资料。

本科和硕士会作为不同教育经历保留。你可以选择本轮校招使用哪段经历，避免把两个专业、两个毕业年份混在一起。项目内容也会区分「已实现」「已知局限」和「计划实现」，计划不会被当成已经做过的成果。

在「查看完整分析正文」里，可以看到程序用已保存、已核对的资料组成的完整文字；项目段落保留原样。解析漏掉的实习或科研可以写进「补充经历」。API 与 ChatGPT 分析包都会使用这份正文，删掉的解析错误不会从原始简历再次混进来。

### 2. 把关注的公司加进来

在「**招聘来源**」里搜索公司，选择支持自动导入的来源，先预览范围，再设置关键词和检查间隔。后台会逐步导入，并按关注配置继续检查更新。

也可以点击顶部「**一键导入全部岗位**」，一次读取全部已适配来源的当前校招范围。导入在后台继续，刷新或离开页面后仍可查看进度；失败来源可单独重试，已有岗位会去重。这是一次性导入，不会改动已有关注设置，也不会自动调用大模型做深度分析。完整导入每 30 分钟可发起一次，目录中仅提供官网入口的来源不参与。

已有适配包括小红书、腾讯、百度、阿里巴巴、京东、哔哩哔哩等公司，银行技术岗位已支持招商、中信、中行软件中心与信息科技运营中心，以及交行总行金科。证券校招新增招商证券、华泰总部、中信建投、国信、银河、中金，可以按“银行”或“证券”筛选。也提供部分外企和制造业入口。**目录里有官网链接，不一定代表已经能自动抓取。** 每个来源的状态、招聘范围和验证记录见 [招聘来源清单](docs/campus-source-inventory.md)。

### 3. 先筛，再分析，别让模型钱包加班

在「**岗位雷达**」里先看主投及相关方向，再按公司、城市和状态缩小范围。 新版展示整体适配结论、关键优势和待确认问题。同公司另做完整材料比较，不用为“热爱技术”逐条补证明。本地初筛不调用模型；后端、服务端等常见名称会归一，语言要求的「任选一种」也会单独处理。它使用有限的规则和词表，复杂要求仍要看原文。

列表上方只保留搜索、公司、城市和排序。用「全部岗位 / 主投相关 / 稍后看 / 投递计划 / 已投递」切换浏览范围，切换时保留公司、城市和关键词；分析状态、初筛建议、多城市和常用条件统一放进「更多条件」。已启用的额外限制会在外面显示为可移除标签，点「清空条件」可回到完整列表。勾选后可点「已选」查看全部选择，包括默认收起的岗位，返回其他范围也不会丢掉勾选。可以按整体适配、初筛、更新时间、收录时间或公司名称排列，也能切换顺序；未知和过期的评分不会抢到前面。启用的条件会变成可单独移除的小标签，返回页面时保留筛选和页码。城市的不同写法也会合并，比如「Hangzhou」「杭州市」「杭州市-余杭区」都算杭州；只写「浙江省」的岗位仍保留为省份，不猜具体城市。地点匹配和意向城市使用同一套规则，招聘原文不改。

点开岗位，右侧就能查看匹配依据、原文和准备清单。需要深入比较时，勾选岗位后发起「深度分析」：**先检查完整外发资料，再确认开始**。默认每轮最多处理 30 个待分析岗位，成功结果会保存，失败项可以单独重试。

相同资料和岗位会复用整体报告；技能、完整项目或 JD 变化后提示更新。旧版逐项分数留作历史参考，新分析不再按满足条数计分。

### 4. 比完岗位，把下一步记下来

在「同公司对比」选择候选范围，核对完整资料后生成首选、备选与取舍；每次最多16个岗位，无需先逐岗分析。同范围报告可以复用，查看报告和准备清单不调用分析模型。选定岗位后加入投递计划，从清单准备项目讲解和待核实项。

如果一家公司只允许投一到三个岗位，可以在「投递进展」维护同公司、同批次的限投规则；创建计划时会检查已占用的名额。规则需要你根据官网填写，实际投递仍由你在官网完成。

实际投递数达到上限后，岗位雷达会自动收起规则内其余未投、未计划的岗位；勾选「显示限投已满岗位」就能再看到，岗位与分析结果仍保留。计划占满不会触发收起，同公司其他批次也不受影响。

投递之后记录阶段、所用简历和备注；面试后补上结果与复盘。再打开「今日待办」，看看近期截止、面试、待复盘和分析失败项，求职进度就不用全靠脑内缓存啦。

## 模型怎么选？资料会发到哪里？

「**模型设置**」内置 OpenAI 和 DeepSeek 预设。填入自己的 API 密钥，再选模型即可；也可以使用部署者配置的服务器默认模型。

- **原始简历文件和原始文字不上传。** 简历导入只发送你确认过的脱敏预览；自动遮盖可能漏项，请检查姓名、联系方式及项目中的敏感文字。
- **保存后的求职资料和项目事实会写入 CampusTrace 的 MySQL。** 默认部署时，数据库在本机 Docker 中。
- **网页 API 密钥按账号保存在当前浏览器。** 本地存储未加密；调用时会经 CampusTrace 服务转发给对应模型提供商，不写入项目数据库。
- **API 调用会产生提供商费用。** 项目里的每日上限限制岗位匹配调用次数，不是整个模型账号的金额上限；失败或超时的请求也可能计费。

不想配置 API？本地筛选、投递记录和面试管理照常用。还可以批量选择岗位，点击「**导出到 ChatGPT**」，核对分析包后自行上传或粘贴到聊天中。这个导出操作不调用模型；ChatGPT 按包内格式返回 JSON 后，点击「**导入聊天分析**」，上传结果文件或粘贴 JSON，预览会集中列出核对问题，通过的岗位可以先确认导入；其余岗位可复制修正清单回到聊天修改。新版返回整体报告，还能一起回传同公司排序，导入后可继续查看准备清单；这一来一回不需要 API 密钥。

## 求职问答里的 Agent 能做什么

在「更多工具 → 求职问答」里，可以问它岗位依据、项目经历、准备方向或分析任务的情况。它会调用项目允许的查询工具，读取你有权限访问的数据。

已有匹配结果可以直接查询，不会因为问一句问题就重新跑整批深度分析。涉及创建投递计划、修改关注等允许的写操作时，它先给出预览，**你点确认后才执行**。选用外部模型进行问答时，问题和相关工具资料会发送给该提供商。

展开「我的记忆与讨论记录」，可以保存、修改和遗忘偏好与决定，也能继续之前的讨论。想让它记住事情，可以说“记住：主投 Go 后端，优先上海”，核对预览后再确认。记忆不会被当成能力证明；资料或记忆改了，旧摘要就不再作为当前依据。

还有可选的「Go 练习」：运行 `./campustrace practice start` 后，粘贴实现和测试，主动运行验证自己的理解。练习在有时间、资源和网络限制的独立容器中执行，结果能保存、重新载入。使用方式与边界见 [资料、记忆与练习说明](docs/agent-workspace.md)。

常用任务可以直接选择“同公司岗位取舍”“岗位面试准备”“复盘与复习”或“今天的求职待办”。每一步保存进度，中断后继续剩下的查询。还可开启招聘变化提醒、连接自己选定的 MCP 学习资料，并为问答设置模型分工和调用预算。具体用法见 [求职助手说明](docs/agent-harness.md)。

复习笔记可以放到「更多工具 → 学习资料」。默认本地关键词搜索，也可预览确认后建立语义索引，用自己的话找资料；重排序按需启用。检索模型在「模型设置」单独配置，密钥留在浏览器。用法与效果检查见 [学习资料检索](docs/knowledge-retrieval.md)。

未配置外部模型时，提供一个能力有限的离线路由器，方便查看工具流程。它不是完整的聊天大模型。

## 幕后怎么做的

这也是一个 Go 后端实践项目。除了页面上的功能，下面这些实现解决的是使用中实际会遇到的问题：

| 问题 | 实现 |
| --- | --- |
| 岗位更新要入库，还要可靠地安排后台处理 | MySQL 事务与 Outbox 记录任务，Redis Stream 分发，Worker 通过数据库幂等处理重复消息 |
| 网页关了，分析进度不能全丢 | MySQL 保存任务和逐项进度；服务中断后保留已完成结果，重新核对资料再继续 |
| 改了简历，旧分析不能冒充新结果 | 按完整资料、岗位原文、模型与候选集合绑定缓存，提交时重新核对输入 |
| 一家公司最后一个投递名额，不能被并发占两次 | 同一事务检查限投规则、名额和记录版本 |
| 抓取和模型调用不能无限开 goroutine | 有界 Worker、独立并发限制、超时、限流、退避重试与失败队列 |
| 出了问题，要知道卡在哪一步 | 请求编号、任务阶段事件、Prometheus 指标，以及可复现的性能测量 |
| 分析服务需要独立运行 | 使用 [KanaRPC-Go](https://github.com/KanaDoodle/KanaRPC-Go) 的公开接口，配合 etcd 发现两个 Analysis 实例 |

招聘观察链路把「抓到了什么」「原文依据是什么」「规则如何判断」分开保存。页面还能访问，不会仅凭这一点就说岗位仍开放；已有投递也不会因为岗位关闭而自动终止。

## 开发与测试

默认把应用和依赖一起放进 Docker。如果要修改后端并在本机运行：

```sh
./campustrace stop
make deps
make dev-run
# 结束本机开发服务
make dev-stop
```

普通检查不需要模型密钥；前端测试需要 Node.js。

```sh
export GOWORK=off
go build ./...
go vet ./...
go test -count=1 ./...
go test -race -count=1 ./internal/...
node --test web/*.test.cjs
make verify-boundary
```

真实依赖集成测试用 `RADAR_RACE=1 ./scripts/verify-radar.sh`，会建立隔离测试库；Agent 评测用 `make eval`，默认使用合成问题与脚本模型，不产生外部模型费用。性能数据是测试场景的测量结果，具体条件见 [性能验证](docs/performance.md)。

## 目前还没学会的事 (´・ω・`)

招聘网站改版、接口限制或网络问题都可能影响导入；没有适配的公司需要手动查看。扫描版简历暂不支持 OCR，复杂岗位语义和模型推断也仍需要人工核对。

项目定位是个人求职工具：不提供自动投递，通知目前以站内提醒为主，准备清单勾选不跨设备同步。更多容量、认证和运维限制见 [架构说明](docs/architecture.md#当前限制)。

遇到不好用的地方，欢迎提 Issue。带上操作步骤和脱敏后的错误提示就很有帮助；真实简历、API 密钥和数据库备份请留在自己手里。
