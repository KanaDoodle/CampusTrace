# CampusTrace 前端设计预览

这是一份独立的交互原型，供确认页面结构和视觉方向。所有岗位、匹配分数、资料和模型状态都是示例；不访问产品 API，不读取现有账号、简历、密钥或数据库，不发起模型请求。页面内的修改只存在于本次预览，刷新即可恢复。

本地打开：在本目录运行 `python3 -m http.server 8090 --bind 127.0.0.1`，访问 `http://127.0.0.1:8090`。

## 设计方向

CampusTrace 是个人校招决策工具。页面的主要任务是帮助用户选择值得进一步核对的岗位，并能追溯判断依据。

- 背景 `#F3F6FA`，工作区域 `#FFFFFF`，正文 `#182A42`，次要文字 `#526477`，操作强调 `#16745B`，提醒 `#996025`。
- 使用本机苹方、微软雅黑及系统字体；正文 14px，页面标题 28px，岗位名称 15px。原文摘录保持正常阅读字号，不把业务内容排成代码。
- 固定左侧导航，主区域左对齐。桌面以列表为主；岗位详情在侧边抽屉打开，关闭后保留筛选、滚动和选择。窄屏使用简化导航和全屏详情。
- 匹配结论先展示，依据按需展开；本地初筛与模型分析有明确标识。覆盖度不足时显示无法可靠评分，不能用一个漂亮分数掩盖缺失依据。
- 批量操作在选择岗位后出现。外发核对和分析设置在独立对话框中完成，核对资料仍是启动分析前的必要步骤。

布局：

```text
导航 | 岗位库                         来源 / 分析设置
     | 公司切换 · 搜索 · 城市 · 分析状态
     | 选择 | 岗位与地点 | 初筛建议 | 核心匹配 | 状态
     | 岗位列表 …                          | 详情抽屉
     | 已选数量                  导出 / 深度分析
```

## 可核对的交互

1. 搜索、公司／城市／分析状态筛选、排序、空结果恢复。
2. 岗位多选、全选当前结果、清空选择、跨筛选保留选择。
3. 岗位详情的结论、证据和原文；键盘 Escape 关闭并回到触发按钮。
4. 批量分析外发核对、默认禁止启动、明确同意后模拟进度；ChatGPT 分析包预览。
5. 求职资料的分区维护、项目事实展开、简历导入示例流程。
6. 模型预设切换、分析设置、来源信息和投递计划示例。

## 落地边界

确认设计后再接入现有接口，沿用当前脱敏、外发确认、批量分析、缓存、预算、暂停／续跑／重试和草稿逐项确认逻辑。本原型中的示例结果不能作为真实岗位推荐，也不表示已经更换现有前端。

## 正式接入

已按此原型将布局接入 `web/` 的正式页面。正式产品使用现有 API 和真实账号数据；本目录仍保留独立示例，作为设计参考。
